# Flash 存储与日志可靠性

## NOR、NAND 与擦写单位

NOR 常用于可直接寻址读取或 XIP，NAND 常用于较大容量并需要相应 ECC、坏块管理和控制器支持。SPI/QSPI 描述传输接口，NOR/NAND 描述存储组织，不能将二者当作同一维度分类。

Flash 擦除以扇区或块为单位，编程以器件允许的粒度进行，页编程还有页边界限制。位值通常只能在编程方向变化，恢复相反方向需擦除。具体页、扇区大小和最大频率必须以器件手册为准；分片下载不应导致每片都重复擦除整个扇区。

## 掉电一致性

数据、长度、版本/序列号和校验构成可验证记录，先写内容，再按可恢复规则提交有效标志。元数据更新可用冗余槽或日志式记录，启动时选择最新且有效的一份。写入回读及 CRC 发现部分错误，但不自动使跨多次写入事务具有原子性。

循环写入能分散部分擦写负担，完整磨损均衡还需管理热数据与冷数据、坏块及回收。备份寄存器只在对应供电域保持，不能未经验证就把它当作所有掉电情形下的可靠进度存储。

## 异步日志与背压

业务任务生成有界日志记录，日志任务批量写入；ISR 只提交满足中断安全约束的事件，不同步执行格式化与存储。优先级不变也可通过批处理、减少重复格式化、限制每轮工作量及合适 DMA 降低 CPU 占用。

队列满时应明确丢弃策略与丢弃计数，严重错误可保留专用容量。评估指标包括队列峰值、写入延迟、最长阻塞和日志任务 CPU 时间；只看日志条数不能区分格式化、搬运和存储耗时。

## 看门狗与系统健康

健康管理按关键任务的进度与截止期限判断是否喂狗。独立看门狗依相应独立时钟运行，窗口看门狗还限制过早服务；时钟、复位范围及低功耗表现依芯片。OTA 擦除长延时、日志堵塞和任务饿死都必须纳入健康判定。
