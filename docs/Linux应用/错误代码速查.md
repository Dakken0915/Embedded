# Linux 错误代码速查

## 适用范围与编号

以下数值以 Linux 6.6 UAPI 的 `asm-generic/errno-base.h` 和 `asm-generic/errno.h` 为基准，与常见 x86-64 Linux 一致。其他架构或操作系统可能采用不同编号；代码应使用 `<errno.h>` 中的宏，而不是写死数值。这是 Linux 错误码表，不是 ISO C 保证的完整错误集合。

`EWOULDBLOCK` 在 Linux 上与 `EAGAIN` 相等，本表为 **11**，不是 41。采用本表定义时，`EDEADLOCK` 是 `EDEADLK` 的别名，值为 **35**；41、58 没有独立条目。部分架构的 `EDEADLOCK` 则有独立定义，应以目标平台头文件为准。Linux 中 `ENOTSUP` 通常与 `EOPNOTSUPP` 相等，本表为 95。

编号依据：[Linux 6.6 基础错误定义](https://github.com/torvalds/linux/blob/v6.6/include/uapi/asm-generic/errno-base.h)、[扩展错误定义](https://github.com/torvalds/linux/blob/v6.6/include/uapi/asm-generic/errno.h)。跨架构差异与错误名语义见 [errno(3)](https://man7.org/linux/man-pages/man3/errno.3.html)。

## 返回约定

| 接口类别 | 常见错误返回方式 | 取得错误原因 |
| --- | --- | --- |
| 用户态 `open`、`read`、`write` 等 C 库系统调用包装 | 返回 `-1` | 立即保存 `errno`，再用 `strerror(saved_errno)` 或 `perror` 输出 |
| `pthread_create`、`pthread_join`、大部分 pthread 接口 | 直接返回错误编号 | 检查返回码，用 `strerror(rc)`；不能改读 `errno` |
| `sem_wait` 等 POSIX 信号量接口 | 返回 `-1` 并设置 `errno` | 按接口文档检查 `errno`，不能因为用于线程同步就套用 pthread 规则 |
| 内核中约定返回负错误码的函数或驱动回调 | 如 `-EINVAL`、`-ENOMEM` | 读取负返回值；内核不使用用户态线程的 `errno` |
| 内核错误指针接口 | 如 `ERR_PTR(-ENOMEM)` | 使用 `IS_ERR`、`PTR_ERR`；不能只检查 `NULL` |
| libusb 等第三方库 | 库自有的返回码 | 使用相应库的解释函数，不能直接把其负数当作 `-errno` |

实际约定以具体接口为准，例如 `mmap` 失败返回 `MAP_FAILED`，部分标准库函数用 `NULL` 表示失败。`pthread_mutex_lock` 对健壮互斥量返回 `EOWNERDEAD` 时，调用者已经取得锁，还需要修复受保护状态并调用 `pthread_mutex_consistent`，不能简单当作“未持锁”，见 [pthread_mutex_lock 的 POSIX 约定](https://man7.org/linux/man-pages/man3/pthread_mutex_lock.3p.html)。线程接口详见[线程控制](./线程控制.md)。

`errno` 是线程局部的可修改左值，包含头文件即可使用，不要自行声明 `extern int errno`。只有调用结果按该接口约定指示失败时，才能据此解释 `errno`；成功调用不会保证将旧错误清零。对于 `strtol` 等结果可能与错误重叠的接口，应按接口要求在调用前清零，并同时检查结束指针和结果范围。

## 常用错误的处理边界

| 错误 | 常见场景与处理条件 |
| --- | --- |
| `EINTR` | 调用在完成前被信号打断；只有操作允许继续且业务无需退出时才重试。已返回正字节数时按短读/短写处理，不再根据旧 `errno` 重做整次操作。Linux 的 `close` 失败后不应直接重试，以免关闭已经被其他线程复用的描述符 |
| `EAGAIN` / `EWOULDBLOCK` | 非阻塞 I/O 暂时无法完成；等待 `poll`/`epoll` 就绪后重试并再次检查。其他接口也可能用它表示资源暂时不足，不能一律解释为“没有数据”或忙循环 |
| `EINPROGRESS` / `EALREADY` | 非阻塞连接正在建立或上一次连接尚未完成；等待就绪后通过 `getsockopt(SO_ERROR)` 检查最终结果，不能把可写直接当成连接成功，见 [connect(2)](https://man7.org/linux/man-pages/man2/connect.2.html) |
| `EPIPE` | 管道无读者或连接写端不可用；写入还可能引发 `SIGPIPE`，需要事先明确进程的信号策略；socket 可按接口使用 `MSG_NOSIGNAL`，见 [send(2)](https://man7.org/linux/man-pages/man2/send.2.html) |
| `EACCES` / `EPERM` | 访问权限不足与操作不被允许；需结合路径权限、能力、安全策略及具体操作判断，不是所有情况都能靠修改文件模式解决 |
| `EMFILE` / `ENFILE` | 分别涉及进程文件描述符限制与系统打开文件资源限制；区分描述符泄漏、并发数量和系统容量 |
| `ENOSPC` / `EDQUOT` | 分别是空间等资源不足与配额限制；释放普通磁盘空间不一定解除用户或项目配额 |
| `ENOTTY` | ioctl 请求不适用于该对象；并非只说明“不是终端”，还可能是设备不支持该命令 |
| `EOWNERDEAD` / `ENOTRECOVERABLE` | 健壮互斥量的状态恢复问题；持有者退出不代表共享数据仍一致，必须按恢复协议处理 |

`ERESTART`（本表 85）不能与内核内部的 `ERESTARTSYS` 等重启控制值混为一谈；应用是否重试应依据具体用户态接口、信号策略和返回结果。驱动中的 `-EPROBE_DEFER` 等内核内部约定也不属于下面的用户态 errno 表。Linux 关闭描述符的约束见 [close(2)](https://man7.org/linux/man-pages/man2/close.2.html)。

## 别名

| 宏名 | 本表数值 | 关系 |
| --- | ---: | --- |
| `EWOULDBLOCK` | 11 | 与 `EAGAIN` 相等，表示操作将阻塞 |
| `EDEADLOCK` | 35 | 本表中与 `EDEADLK` 相等，其他架构需查头文件 |
| `ENOTSUP` | 95 | Linux C 库中通常与 `EOPNOTSUPP` 相等 |

判断非阻塞结果可写 `err == EAGAIN || err == EWOULDBLOCK`；若在 `switch` 中为二者分别写 `case`，Linux 上会因数值重复而编译失败。

## 保存并输出错误信息

下面是 Linux 用户态 C11 完整程序，只依赖 libc。它以只读方式打开命令行指定路径，最多读取 32 字节，不输出内容；适用于普通文件或具有相应读取语义的对象。读取可阻塞，本例允许被信号打断后继续等待，没有业务停止信号协议。成功的短读不强行补满，读取普通文件返回 0 表示 EOF。编译命令为 `cc -std=c11 -Wall -Wextra -Werror errno_demo.c -o errno_demo`。

```c
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>

int main(int argc, char **argv)
{
    if (argc != 2) {
        fprintf(stderr, "usage: %s PATH\n", argv[0]);
        return 2;
    }

    int fd = open(argv[1], O_RDONLY);
    if (fd == -1) {
        int saved_errno = errno;
        fprintf(stderr, "open: errno=%d (%s)\n",
                saved_errno, strerror(saved_errno));
        return 1;
    }

    unsigned char buffer[32];
    ssize_t count;
    do {
        count = read(fd, buffer, sizeof(buffer));
    } while (count == -1 && errno == EINTR);

    int failed = 0;
    if (count == -1) {
        int saved_errno = errno; // 在日志、close 等后续调用前保存
        fprintf(stderr, "read: errno=%d (%s)\n",
                saved_errno, strerror(saved_errno));
        failed = 1;
    }

    if (close(fd) == -1) { // Linux：失败后不重试该描述符
        int saved_errno = errno;
        fprintf(stderr, "close: errno=%d (%s)\n",
                saved_errno, strerror(saved_errno));
        failed = 1;
    }

    if (!failed && printf("read %zd bytes\n", count) < 0) {
        return 1;
    }
    return failed;
}
```

`strerror` 返回的说明由 C 库和语言环境决定，不适合作为稳定协议字段或字符串匹配条件；判断应使用错误宏。`perror("open")` 输出当前 `errno` 的说明，调用前不能让其他函数覆盖所需错误值。错误字符串接口及 `strerror_r` 的 POSIX/GNU 签名差异见 [strerror(3)](https://man7.org/linux/man-pages/man3/strerror.3.html)。

本机可使用 `errno -l` 查看名称、数值和说明，但该命令来自额外的 moreutils 软件包，并非所有系统默认安装。交叉编译时应查询目标 sysroot 的 `<errno.h>`，不能用宿主机输出代替目标 ABI。驱动返回约定另见[字符设备与 I/O 模型](../Linux驱动/基础理论/字符设备与IO模型.md)。
