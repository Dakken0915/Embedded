# 进程、线程与系统调用

## 资源与调度实体

同一进程的线程共享地址空间、全局对象和通常的文件描述符表，各自具有执行栈、寄存器、线程标识及 TLS 等状态。栈属于同一地址空间，其他线程持有有效地址时仍可能访问它，不是硬件隔离的私有内存。

Linux 以任务等内核结构组织调度与资源共享。线程错误可能影响整个地址空间，但一个进程异常也可能通过共享设备、资源耗尽等影响其他服务；进程隔离不是系统可靠性的绝对保证。

## fork 与写时复制

fork 后父子进程有各自的虚拟地址空间和文件描述符表，部分物理页采用 COW 共享，写入时再建立私有副本。指向同一 open file description 的描述符通常共享文件偏移及相关状态；关闭一方的描述符不会自动关闭另一方的对应描述符。

MAP_SHARED 映射与普通私有 COW 内存不同。多线程进程 fork 后子进程只保留调用线程，继承的锁可能处于其他已不存在的线程持有状态，执行 exec 前须遵循相应异步信号安全约束。

## IPC 与同步

| 机制 | 数据与边界 |
| --- | --- |
| pipe/FIFO | 字节流；匿名管道需通过继承或描述符传递获得访问，不是硬性只能亲缘进程使用 |
| 消息队列 | 提供消息边界和内核管理，仍有大小、数量与阻塞条件 |
| 共享内存 | 多进程访问共同映射，减少载荷搬运，但不自带完整同步或消息边界 |
| 信号 | 异步事件通知，处理函数受异步信号安全限制 |
| Unix/TCP/UDP socket | 本机或网络通信，按协议具有流或数据报语义 |

共享内存必须配套状态机、进程共享同步对象或适当原子协议；共享字节不等于并发访问自动正确。自旋锁忙等，互斥量可能阻塞，读写锁区分访问模式，条件变量等待状态变化；选择取决于上下文及不变量。

## 用户态到内核态

C 库包装按架构 ABI 放入系统调用号和参数，执行体系结构的系统调用指令，进入内核入口进行校验、分派和访问控制，完成后返回用户态。AArch64 常用 svc，x86-64 使用 syscall，RISC-V 使用 ecall，不能将 svc 当作全部 Linux 平台的统一指令。

打开字符设备时，路径解析与 VFS 获得 inode/设备号，字符设备机制找到已注册设备与 file_operations，随后进行对应 open/read/ioctl 等调用。具体内部函数名随版本变化，用户指针必须通过用户访问接口处理。

## ELF 与内核模块加载

exec 读取 ELF，建立 PT_LOAD 等所需映射、用户栈与启动信息，动态映像还通过 PT_INTERP 指定解释器。按需调页可延后真正读入部分页面；动态链接器执行共享库映射及符号重定位，再转交运行库入口。

insmod 则请求加载内核模块，内核检查格式、符号、许可及适用的签名策略，完成分配、重定位和初始化入口调用。模块不是普通用户态共享库；加载成功也不代表目标硬件一定已经匹配并完成 probe。

## AArch64 系统调用与 IRQ

常见 Linux AArch64 系统调用 ABI 使用 x8 保存调用号、x0～x5 保存参数、x0 返回结果，经 svc #0 进入异常向量。C 库还会将内核错误返回转换为相应 errno 约定；SVC 立即数并非通用的系统调用号。

同步异常来自当前执行指令，如系统调用或访问故障；IRQ 是异步外部事件。异常入口依据来源和栈状态进入对应向量，保存必要通用寄存器及 ELR/SPSR 等信息，再交给 Linux 的异常或中断分派。处理器不会像 Cortex-M 一样为 Linux 自动建立同款八寄存器栈帧。

`b` 直接分支，`bl` 还保存链接地址，`br`/`blr` 使用寄存器目标，`ret` 用于子程序返回，`eret` 用于异常返回并恢复相应状态。普通函数返回与异常返回不能互相替代。
