# POSIX 线程控制与同步

本文采用 Linux、POSIX Threads 与 C11，依赖 `<pthread.h>`、`<semaphore.h>`，编译时使用 `-pthread`。线程共享地址空间，互斥与同步分别用于保护共享不变量和等待状态变化；调度顺序本身不构成同步保证，`volatile` 也不能消除数据竞争。

## 创建、参数与属性

```c
int pthread_create(pthread_t *thread, const pthread_attr_t *attr,
                   void *(*start_routine)(void *), void *arg);
```

| 参数 | 含义与生命周期 |
| --- | --- |
| `thread` | 成功后写入线程标识；失败后不能用它执行 join/detach |
| `attr` | `NULL` 使用默认属性；自定义属性先 `pthread_attr_init`，用完 `pthread_attr_destroy` |
| `start_routine` | 签名必须为 `void *function(void *)`；返回值由 join 获取 |
| `arg` | 原样传递指针，不复制指向的对象；必须存活至线程最后一次访问 |

新线程可能在 `pthread_create` 返回前执行，不能把后续初始化当作隐含前提。多参数通常封装在结构体中，不应将循环变量地址重复传给多个线程。`pthread_t` 是不透明标识，用 `pthread_equal` 比较，不能假设它就是 Linux TID 或可移植的整数。

属性可设置 detached 状态、栈大小和调度参数。栈须满足实现要求，不能把 `PTHREAD_STACK_MIN` 当成业务所需容量。显式实时调度还涉及 `PTHREAD_EXPLICIT_SCHED`、策略优先级及系统权限，创建时可能返回 `EPERM`。

大部分 pthread 接口成功返回 0，失败直接返回错误编号，应使用 `strerror(rc)`；它们不采用普通系统调用的 `-1/errno` 形式。见 [pthread_create 手册](https://man7.org/linux/man-pages/man3/pthread_create.3.html)。

## 退出、回收与停止协议

入口函数 `return pointer` 与 `pthread_exit(pointer)` 结束当前线程。返回值不能指向线程已经结束生命周期的局部对象。默认线程可 join，`pthread_join` 等待结束并回收相关资源；detached 线程结束时自动回收线程资源，不能再 join。同一线程只能由一个确定的回收者处理，不能同时 join 与 detach。

从 `main` 返回或调用 `exit` 会终止整个进程。可靠停止通常采用共享停止标志、唤醒阻塞等待和 join 的组合；仅设置标志无法唤醒正在条件变量、信号量或设备 I/O 中等待的线程。

`pthread_cancel` 是取消请求，不等同于立即终止。默认延迟取消在取消点生效，条件变量等待属于取消点；取消清理处理程序需要释放锁和其他资源。异步取消可能打断任意临界区，不宜作为常规停止方式。

## 互斥量与共享不变量

| 接口 | 行为 |
| --- | --- |
| `PTHREAD_MUTEX_INITIALIZER` / `pthread_mutex_init` | 静态/动态初始化，二选一，不对已初始化对象重复初始化 |
| `pthread_mutex_lock` | 获取锁，竞争时可能等待 |
| `pthread_mutex_trylock` | 立即尝试，忙时返回 `EBUSY` |
| `pthread_mutex_unlock` | 由持有者解锁 |
| `pthread_mutex_destroy` | 所有使用者退出且无人持有或等待后销毁 |

对同一状态的全部冲突访问须使用同一保护协议。默认互斥量不保证递归加锁行为，多把锁应规定一致的获取顺序。缩短临界区可减少竞争，但阻塞 I/O 是否能移出锁必须根据共享不变量决定。

robust mutex 的 `EOWNERDEAD` 表示调用者已经取得锁，但受保护状态可能不一致；修复后调用 `pthread_mutex_consistent`，不能把它当作普通“未获得锁”错误。

## 条件变量与谓词

条件变量本身不保存事件计数，真正条件由共享状态表达。调用 `pthread_cond_wait` 前必须持有互斥量；等待操作原子地释放锁并阻塞，返回前重新取得锁。返回成功也可能是虚假唤醒，或者条件已被其他消费者改变，因此必须用 `while` 重新判断谓词。

`pthread_cond_signal` 唤醒一个等待者，`pthread_cond_broadcast` 唤醒全部等待者。常用协议是在同一互斥量下修改谓词并通知；停止时广播，使所有等待者都有机会观察退出条件。没有等待者时通知不积累，不能用条件变量替代有计数的消息队列。

以下完整程序实现单槽生产与消费，包含自然结束、条件等待、广播与 join。对象由主线程持有，直到工作线程回收后才销毁；示例不使用取消，pthread 同步设施失败时直接终止进程，避免在破坏的同步状态上继续执行。

```c
#define _POSIX_C_SOURCE 200809L
#include <pthread.h>
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct channel {
    pthread_mutex_t mutex;
    pthread_cond_t changed;
    bool full;
    bool closed;
    unsigned value;
    unsigned sum;
};

static void check(int rc)
{
    if (rc != 0) {
        fprintf(stderr, "%s\n", strerror(rc));
        exit(EXIT_FAILURE);
    }
}

static void *consumer(void *arg)
{
    struct channel *c = arg;
    check(pthread_mutex_lock(&c->mutex));
    for (;;) {
        while (!c->full && !c->closed)
            check(pthread_cond_wait(&c->changed, &c->mutex));
        if (!c->full && c->closed)
            break;
        c->sum += c->value;
        c->full = false;
        check(pthread_cond_broadcast(&c->changed));
    }
    check(pthread_mutex_unlock(&c->mutex));
    return NULL;
}

int main(void)
{
    struct channel c = {
        .mutex = PTHREAD_MUTEX_INITIALIZER,
        .changed = PTHREAD_COND_INITIALIZER
    };
    pthread_t thread;
    int rc = pthread_create(&thread, NULL, consumer, &c);
    if (rc != 0) {
        fprintf(stderr, "pthread_create: %s\n", strerror(rc));
        check(pthread_cond_destroy(&c.changed));
        check(pthread_mutex_destroy(&c.mutex));
        return EXIT_FAILURE;
    }
    for (unsigned i = 1; i <= 100; ++i) {
        check(pthread_mutex_lock(&c.mutex));
        while (c.full)
            check(pthread_cond_wait(&c.changed, &c.mutex));
        c.value = i;
        c.full = true;
        check(pthread_cond_broadcast(&c.changed));
        check(pthread_mutex_unlock(&c.mutex));
    }
    check(pthread_mutex_lock(&c.mutex));
    c.closed = true;
    check(pthread_cond_broadcast(&c.changed));
    check(pthread_mutex_unlock(&c.mutex));
    check(pthread_join(thread, NULL));
    check(pthread_cond_destroy(&c.changed));
    check(pthread_mutex_destroy(&c.mutex));
    printf("sum=%u\n", c.sum);
    return c.sum == 5050 ? EXIT_SUCCESS : EXIT_FAILURE;
}
```

```bash
cc -std=c11 -Wall -Wextra -Werror -pthread thread_control.c -o thread_control
./thread_control
```

`pthread_cond_timedwait` 使用绝对截止时间。默认条件变量通常采用 `CLOCK_REALTIME`；Linux 可在初始化属性中选择 `CLOCK_MONOTONIC` 以避免墙上时钟调整影响超时。返回 `ETIMEDOUT` 后仍持有锁，仍需检查谓词与退出条件。见 [条件变量等待语义](https://man7.org/linux/man-pages/man3/pthread_cond_wait.3p.html)。

## 信号量与资源计数

`sem_init(&sem, 0, value)` 创建进程内共享的未命名信号量；`pshared` 非零表示供共享内存中的多个进程使用，信号量对象本身也必须位于共同映射中。`sem_wait` 减少一个可用计数，计数为零时等待；`sem_post` 增加计数并可能唤醒等待者。

信号量没有互斥量的线程所有权限制。资源池常先 wait 后 post；事件通知可以由生产者先 post，再由消费者 wait，也可以由不同线程执行。不能将“必须同一线程、必须先 P 后 V、次数任意增加”当作统一规则；计数应与资源或事件模型一致，post 还可能因达到 `SEM_VALUE_MAX` 返回 `EOVERFLOW`。

下面是可编译函数片段，用于等待已有信号量。`sem_*` 通常失败返回 -1 并设置 `errno`；只有策略允许继续等待时才重试 `EINTR`，需要响应停止信号的业务应另行退出。

```c
#include <errno.h>
#include <semaphore.h>

int wait_token(sem_t *sem)
{
    int rc;
    do {
        rc = sem_wait(sem);
    } while (rc == -1 && errno == EINTR);
    return rc;
}
```

`sem_trywait` 没有可用计数时返回 `EAGAIN`。`sem_timedwait` 还可返回 `ETIMEDOUT`。销毁前必须保证没有阻塞者且不再有线程访问；不能用 `sem_destroy` 作为唤醒或强制终止手段。见 [sem_wait 手册](https://man7.org/linux/man-pages/man3/sem_wait.3.html)。

## 三类工具的边界

| 工具 | 保护或等待的对象 | 是否积累通知 | 关键约束 |
| --- | --- | --- | --- |
| 互斥量 | 共享状态的不变量 | 不表示事件数量 | 持有者解锁，统一锁顺序 |
| 条件变量 | 互斥量保护的谓词 | 否 | 循环检查，先修改状态再通知 |
| 信号量 | 可用资源数/事件数 | 是，受计数上限限制 | 明确每个计数代表什么 |

POSIX 线程原语与内核的 `mutex`、`spinlock_t`、等待队列属于不同 API 和执行环境；内核上下文约束见 [内核同步与互斥](../Linux驱动/同步与互斥.md)。
