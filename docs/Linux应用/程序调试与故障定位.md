# 程序调试与故障定位

## ELF 符号与调用栈

调试信息将地址关联到源码、类型和行号；优化、内联、尾调用和缺少帧指针可能改变栈回溯结果。保留与运行映像完全匹配的 ELF、库、构建标识和配置，才能解释故障地址。远程板卡调试还需匹配目标架构与 sysroot。

```shell
gdb ./application
# 以下为 GDB 内命令：
# break main
# run
# info threads
# thread apply all bt
# info registers
# disassemble
```

watch 设置数据观察点，能定位某些意外写入，但硬件观察点数量和范围有限。Core dump 反映故障时快照，attach 或断点会改变实时行为；高频路径可用有界跟踪和时间戳降低扰动，但不能声称完全无损。

## 越界、释放后使用与泄漏

越界和释放后使用可能延迟暴露，崩溃位置未必就是破坏位置。主机可构建启用 AddressSanitizer/UndefinedBehaviorSanitizer 的可复现程序，线程数据竞争另用对应工具；目标硬件可结合 MPU、栈水位和保护哨兵。清空一个指针不消除其他别名。

```shell
cc -g -O1 -fsanitize=address,undefined -fno-omit-frame-pointer source.c -o application
```

泄漏需结合分配次数、未释放对象及持续趋势判断；缓存与内存池增长不必然是泄漏。工具会增加内存和时间开销，需与产品时序验证区分。
