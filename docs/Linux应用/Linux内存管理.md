# Linux 内存管理

## 用户态分配接口

| 接口 | 行为与限制 |
| --- | --- |
| malloc/free | 分配和释放动态存储；分配器可从 brk 或 mmap 等取得底层内存 |
| calloc | 按元素数量分配并清零，仍需检查失败 |
| realloc | 调整容量，可移动；失败保留旧对象 |
| 匿名 mmap | 建立虚拟映射，页面通常按需建立；不保证物理连续 |
| posix_memalign | 返回满足指定对齐的用户虚拟地址，不等于取得 DMA 地址 |
| alloca | 非标准栈分配扩展，函数返回失效，失败风险与栈容量相关 |

malloc 何时使用 mmap 由实现、版本、运行历史和调优参数决定，128 KB 不是统一边界。分配虚拟地址成功也不必然说明物理页已经实际分配。

内核对象分配与寄存器映射见 [内核内存与地址映射](../Linux驱动/内核内存与地址映射.md)。

## 虚拟地址、VMA、页表与 TLB

VMA 描述一段具有相应权限、来源和操作的虚拟地址范围，不等于逐页映射记录。页表记录转换与权限，TLB 缓存近期转换；修改页表后按架构要求维护 TLB 和可见性。

页表层级随架构、地址宽度与页面粒度变化。Linux 的抽象层级可包括 PGD、P4D、PUD、PMD、PTE，部分级在具体配置中折叠。AArch64 的 4 KB 页面、48 位虚拟地址是常见四级示例，但不代表所有 ARM64 配置。

缺页时先判断地址是否有合法 VMA、权限是否允许，再按匿名内存、文件映射、COW 等路径建立或修改页映射；访问非法时向进程发送相应信号。缺页不一定意味着从磁盘读取，也可能仅分配零页或复制共享页。

`virt_to_phys` 只适用于其约定的内核地址范围，不能用于任意用户地址、vmalloc 地址或设备 DMA 地址。获取 PFN 也需要先明确地址来源、映射是否存在及页是否被正确固定。

## 内存占用的不同口径

虚拟地址规模 VSZ、驻留集 RSS、按共享比例分摊的 PSS、文件页缓存及 slab 表示不同资源。多个进程 RSS 相加会重复计算共享页；进程占用不高而系统可用内存减少，也可能与页缓存、内核对象或驱动缓冲有关。

```shell
cat /proc/meminfo
cat /proc/PID/status
cat /proc/PID/smaps_rollup
```

以实际 PID 替换占位符，读取权限和内核配置决定接口是否可用。缓存可回收程度、匿名内存与持续增长的不可回收对象应分别分析，不能把所有已用内存都当作泄漏。

## AArch64 4 KB 页的地址拆分示例

在 48 位虚拟地址、4 KB 页、四级转换这一特定条件下，页内偏移为 bit[11:0]，其上四级索引分别为 bit[47:39]、[38:30]、[29:21]、[20:12]，每级 9 位、每表 512 项。39 位虚拟地址的常见三级配置省去最高一级索引。大块映射可在中间级终止转换，不能对所有虚拟地址都假设到最后一级。

TTBR、TCR 和页表项中的输出地址及属性共同决定转换；TTBR0/TTBR1 的选择与地址区配置有关。页大小变为 16 KB/64 KB、VA 宽度变化或扩展启用时，上述位段需要重新推导。
