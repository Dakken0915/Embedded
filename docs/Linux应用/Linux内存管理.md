# Linux 内存管理

## 应用层内存申请

`alloc`：向栈申请内存,因此无需释放

`malloc`：分配的内存是位于堆中的,并且没有初始化内存的内容,因此基本上`malloc`之后,调用函数`memset`来初始化这部分的内存空间

`calloc`：自动把分配出来的内存清零

`realloc`：则对malloc申请的内存进行大小的调整.申请的内存最终需要通过函数`free`来释放



## 底层驱动内存申请

###  kmalloc

```C
void* kmalloc(size_t size, gfp_t flags)；
```

`kmalloc()` 申请的内存位于物理内存映射区域，而且在物理上也是连续的，它们与真实的物理地址只有一个固定的偏移，因为存在较简单的转换关系，所以对申请的内存大小有限制，不能超过128KB

**`flag`：**

- **GFP_ATOMIC** —— 分配内存的过程是一个原子过程，分配内存的过程不会被（高优先级进程或中断）打断；
- **GFP_KERNEL** —— 正常分配内存；
- **GFP_DMA** —— 给 DMA 控制器分配内存，需要使用该标志（地址范围约束）。

对应释放函数：

```C
void kfree(const void* objp);
```

### kzalloc()

 与 `kmalloc()` 非常相似，参数及返回值是一样的，额外附加了 **__GFP_ZERO** 标志。所以它除了申请内核内存外，还会对申请到的内存内容清零。

### vmalloc()

```C
void* vmalloc(unsigned long size);
```

`vmalloc()` 函数则会在虚拟内存 空间给出一块连续的内存区，但这片连续的虚拟内存在物理内存中并不一定连续。由于 `vmalloc()` 没有保证申请到的是连续的物理内存，因此对申请的内存大小没有限制，如果需要申请较大的内存空间就需要用此函数了。

对应释放函数：

```C
void vfree(const void* addr);
```



## 虚拟内存 & 物理内存

1. 直接使用物理地址的三大痛点
   - 物理内存有限，无法给每个进程分配完整寻址空间
   - 进程无隔离，可互相篡改数据，不安全
   - 程序地址写死，加载位置变化就寻址失败
2. **虚拟内存**：每个进程独立拥有一份连续虚拟地址空间，数据分散在物理内存，部分可换出到磁盘，按需调入。
3. **虚拟地址**：程序内部使用的地址，属于进程虚拟地址空间；CPU 访问时由 MMU 完成逻辑地址 → 物理地址转换。
4. **MMU**：内存管理单元，负责地址翻译、页表查找、内存权限检查。



## 页式内存管理

- **页 Page**：虚拟内存管理基本单位，Linux 默认 4KB。进程 4G 虚拟空间划分为多个虚拟页。
- **页框 Page Frame**：物理内存同样按 4KB 划分，是物理内存分配单元。
- **页表 Page Table**：每个进程独立拥有，存放【虚拟页号 → 物理页框号】映射关系，表项叫**页表项 PTE**；MMU 查表完成地址转换。
- **TLB（Translation Lookaside Buffer，快表）**
  - 是 CPU 内部高速缓存，缓存近期常用的页表项（虚拟页→页框映射）
  - 目的：避免每次地址访问都去内存查页表，降低地址翻译开销
  - TLB 命中：直接拿到物理页框；TLB 缺失（TLB miss）：访问内存页表，同时更新 TLB
  - 进程切换时需要刷新 TLB，防止地址映射错乱
