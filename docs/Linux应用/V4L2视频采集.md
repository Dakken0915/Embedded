# V4L2 视频采集与缓冲区

## 设备与格式

打开 `/dev/videoX` 后，通过 `VIDIOC_QUERYCAP` 检查视频采集和流式缓冲能力。枚举格式后用 `VIDIOC_S_FMT` 请求像素格式和分辨率，并读取返回值确认实际采用的参数。步长 `bytesperline`、图像容量 `sizeimage`、多平面布局和实际有效字节数不能互相替代。

## MMAP 流程

1. `VIDIOC_REQBUFS` 请求缓冲区，检查实际分配数量。
2. `VIDIOC_QUERYBUF` 查询各缓冲区大小和偏移，用 `mmap()` 建立映射。
3. 用 `VIDIOC_QBUF` 把缓冲区交给驱动，然后 `VIDIOC_STREAMON` 开始采集。
4. 通过 `poll()` 等待，用 `VIDIOC_DQBUF` 取出完成的缓冲区。
5. 按 `bytesused` 等元数据处理图像，结束后再 `VIDIOC_QBUF` 归还。
6. 退出时 `VIDIOC_STREAMOFF`，解除映射、释放缓冲区并关闭 fd。

缓冲区交给驱动后，应用不能继续把它当作自己的可写图像。异步处理必须在完成前保留该缓冲区的所有权，或复制所需数据；过早归还会使后续采集覆盖图像。

### 单平面 MMAP 缓冲区处理

以下代码用于 `V4L2_BUF_TYPE_VIDEO_CAPTURE` 的单平面 MMAP 采集。调用前须完成格式设置、映射、初始入队和 `STREAMON`，fd 以 `O_NONBLOCK` 打开，并在事件循环中通过 `poll()` 等待可读。映射数组由 `QUERYBUF` 与 `mmap()` 的结果构造。

```c
#include <errno.h>
#include <stddef.h>
#include <time.h>
#include <sys/ioctl.h>
#include <linux/videodev2.h>

typedef struct {
    void *address;
    size_t length;
} CaptureBuffer;

static int retryIoctl(int fd, unsigned long request, void *argument)
{
    int result;
    do {
        result = ioctl(fd, request, argument);
    } while (result < 0 && errno == EINTR);
    return result;
}

/* consume 必须同步完成读取，不能在返回后保留映射区指针。 */
int consumeOneFrame(int fd, const CaptureBuffer *buffers, size_t count,
                    void (*consume)(const void *, size_t))
{
    struct v4l2_buffer frame = {0};
    frame.type = V4L2_BUF_TYPE_VIDEO_CAPTURE;
    frame.memory = V4L2_MEMORY_MMAP;
    if (retryIoctl(fd, VIDIOC_DQBUF, &frame) < 0) {
        return errno == EAGAIN ? 0 : -1;
    }

    if (frame.index >= count ||
        frame.bytesused > buffers[frame.index].length) {
        errno = EIO;
        return -1;  /* 调用者停止采集并清理整个流。 */
    }

    if ((frame.flags & V4L2_BUF_FLAG_ERROR) == 0) {
        consume(buffers[frame.index].address, frame.bytesused);
    }

    struct v4l2_buffer queued = {0};
    queued.type = V4L2_BUF_TYPE_VIDEO_CAPTURE;
    queued.memory = V4L2_MEMORY_MMAP;
    queued.index = frame.index;
    if (retryIoctl(fd, VIDIOC_QBUF, &queued) < 0) {
        return -1;
    }
    return 1;
}
```

返回 0 时重新等待就绪；返回 -1 时记录错误并执行流清理，不能继续假定全部缓冲区仍在队列中。带 `V4L2_BUF_FLAG_ERROR` 的帧在此被丢弃并归还。多平面设备还需要 `v4l2_plane` 数组，不能仅替换 `type` 后沿用本例。缓冲区交换语义见 [Linux VIDIOC_QBUF / VIDIOC_DQBUF](https://www.kernel.org/doc/html/latest/userspace-api/media/v4l/vidioc-qbuf.html)。

## 其他 I/O 方式

Read/Write 方式通过系统调用转移图像数据，支持情况由驱动决定。USERPTR 使用应用提供的缓冲区，DMABUF 可在支持的设备之间共享缓冲区。MMAP 避免将采集数据再次复制到独立用户缓冲区，但不表示整个视频处理链没有拷贝。

## Framebuffer 显示缓冲

Framebuffer 的显示布局由可变屏幕信息中的分辨率和像素格式，以及固定屏幕信息中的 `line_length` 等参数共同决定。每行起始地址应按实际 stride 计算，不能假设 `line_length == xres * bytes_per_pixel`；像素位域和 `bits_per_pixel` 也须用于确认像素格式。通过 `mmap()` 映射 framebuffer 后，写入范围必须受映射长度约束。

使用双缓冲时，应用先绘制非扫描缓冲，再在垂直同步或驱动支持的切换点提交显示页，避免显示控制器读取期间改写同一帧。采集、处理与显示可由有界队列解耦；实时预览常选择丢弃过期帧并保留最新帧，以限制延迟。队列容量、缓冲所有权和缓存一致性仍须明确，不能以无限堆积来掩盖消费速率低于采集速率的问题。

## YUV 与 RGB

转换前确认 YUV 的采样比例、排列、色彩空间及量化范围。YUYV、NV12 与平面 YUV 不能按同一种字节布局读取。查表或定点计算可降低转换开销，但系数与偏移必须匹配源格式；输出还需做范围裁剪。不能仅凭 Y、U、V 三个名称选定一组通用系数。

## YUYV 转 RGB 的定点示例

以下函数仅适用于 BT.601、有限量程、YUYV 单行，两像素共享 U/V，输入长度至少为 width×2，输出至少为 width×3。width 须为偶数，调用方还须检查乘法容量溢出；逐行处理时分别采用实际输入步长和输出步长。它不适用于 NV12、多平面或其他色彩空间。

```c
#include <stddef.h>
#include <stdint.h>
static uint8_t clipChannel(int value)
{
    return value < 0 ? 0 : value > 255 ? 255 : (uint8_t)value;
}
void yuyvRowToRgb(const uint8_t *source, uint8_t *target, size_t width)
{
    for (size_t x = 0; x < width; x += 2) {
        int u = (int)source[1] - 128;
        int v = (int)source[3] - 128;
        for (unsigned pixel = 0; pixel < 2; ++pixel) {
            int y = (int)source[pixel * 2] - 16;
            if (y < 0) y = 0;
            target[0] = clipChannel((298 * y + 409 * v + 128) / 256);
            target[1] = clipChannel((298 * y - 100 * u - 208 * v + 128) / 256);
            target[2] = clipChannel((298 * y + 516 * u + 128) / 256);
            target += 3;
        }
        source += 4;
    }
}
```

MJPEG 以压缩帧降低传输量，但引入解码成本和可变帧长；YUYV 是未压缩采样布局，带宽可由分辨率、帧率和每像素平均字节数估算。图像延迟持续增长通常意味着消费端积压，不能仅通过不断加缓冲解决。

## 格式枚举、输入源与控件

`VIDIOC_ENUM_FMT` 按 index 枚举像素格式，`VIDIOC_ENUM_FRAMESIZES` 针对某格式枚举尺寸，`VIDIOC_ENUM_FRAMEINTERVALS` 进一步查询帧间隔。每次初始化请求结构、检查 type 与返回值；离散、连续和步进式返回使用不同 union，不能始终读取 `discrete.width/height`。

`VIDIOC_G_FMT` 获取当前格式，`VIDIOC_TRY_FMT` 可尝试协商而不修改状态，`VIDIOC_S_FMT` 返回实际格式。队列已经分配或处于 streaming 时改格式通常受到限制，应先停止并按协议释放旧缓冲。`V4L2_CAP_DEVICE_CAPS` 存在时使用 `device_caps` 判断当前节点能力，不盲目使用父设备总体 capabilities。

多输入设备可用 `VIDIOC_ENUMINPUT/G_INPUT/S_INPUT` 选择输入；并非所有摄像头都提供多个输入。传统整数控件使用 QUERYCTRL/G_CTRL/S_CTRL；较新或复合类型还需要 QUERY_EXT_CTRL 与 G/S_EXT_CTRLS。

以下 Linux UAPI 函数片段设置亮度，调用前 fd 为有效视频设备；它检查是否可写、数值范围和步长，复用本页 `retryIoctl`。

```c
#include <stdint.h>

int setBrightness(int fd, int value)
{
    struct v4l2_queryctrl query = {0};
    struct v4l2_control control = {0};
    query.id = V4L2_CID_BRIGHTNESS;
    if (retryIoctl(fd, VIDIOC_QUERYCTRL, &query) < 0)
        return -1;
    if (query.type != V4L2_CTRL_TYPE_INTEGER ||
        (query.flags & (V4L2_CTRL_FLAG_DISABLED | V4L2_CTRL_FLAG_READ_ONLY |
                        V4L2_CTRL_FLAG_INACTIVE)) ||
        value < query.minimum || value > query.maximum || query.step <= 0 ||
        ((int64_t)value - query.minimum) % query.step != 0) {
        errno = EINVAL;
        return -1;
    }
    control.id = query.id;
    control.value = value;
    return retryIoctl(fd, VIDIOC_S_CTRL, &control);
}
```

查询成功到设置之间设备状态仍可能变化，最终必须处理 S_CTRL 的错误。摄像头自动曝光、自动白平衡等模式可能使手动控件变为 inactive；不能只按固定 ID 写一个未经查询的值。

采集驱动、video_device 与 vb2 的内核实现见 [V4L2 驱动与 videobuf2](../Linux驱动/多媒体驱动/V4L2驱动.md)。
