# Linux 驱动路线

从“设备如何被发现”开始，而不是直接背 `file_operations`。设备树描述硬件资源，驱动在 `probe` 中获取资源并注册接口，用户态通过设备节点、sysfs、ioctl 或标准子系统 API 使用能力。

## 建议顺序

1. 模块加载、字符设备和 `file_operations`。
2. platform 总线、设备树、`probe/remove` 生命周期。
3. Pinctrl/GPIO，再进入 I2C、Input、USB、V4L2 和 LCD。
4. 中断、并发、DMA、缓存一致性和性能观测。

驱动边界要清晰：硬件错误在驱动内转换成可诊断的错误码，业务策略留在用户态；资源申请按逆序释放，异步回调必须处理设备移除和并发关闭。
