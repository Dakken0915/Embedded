# ESP32 存储与 LVGL 显示

## Flash 分区表

分区 CSV 包含名称、类型、子类型、偏移、大小和标志等字段。应用分区与数据分区分别承担程序映像、配置、文件系统或 OTA 元数据等职责。偏移留空时构建工具按布局及对齐约束计算地址，不能把某块开发板的烧录地址当作全部芯片的固定值。

`factory` 是工厂应用子类型，`ota_0`、`ota_1` 是 OTA 应用槽，`otadata` 通常用于保存引导选择信息。每个应用槽必须能容纳整个映像；更改分区表前需要考虑已有数据迁移和引导兼容性。

## NVS 键值存储

NVS 在 Flash 上保存键值，命名空间隔离不同模块的同名键，适用于参数和状态等小数据。典型流程为初始化分区、`nvs_open()`、按类型读取或写入、`nvs_commit()` 提交，再关闭句柄。写入接口成功不应被误认为已经完成持久化提交。

读取字符串或 blob 时先确定容量，并区分键不存在、类型不匹配与存储错误。分区变化或初始化失败不应直接无条件擦除用户配置。接口说明见 [ESP-IDF NVS 5.2](https://docs.espressif.com/projects/esp-idf/en/v5.2/esp32/api-reference/storage/nvs_flash.html)。

### NVS 参数写入与提交

以下 ESP-IDF 5.2 代码将采样周期存入 `settings` 命名空间。启动阶段先调用 `initializeSettings()` 并检查结果，再读写参数；示例不会在初始化失败时自动擦除原数据。

```c
#include <stddef.h>
#include <stdint.h>
#include "esp_err.h"
#include "nvs.h"
#include "nvs_flash.h"

esp_err_t initializeSettings(void)
{
    return nvs_flash_init();
}

esp_err_t saveSamplePeriod(uint32_t periodMs)
{
    if (periodMs == 0) {
        return ESP_ERR_INVALID_ARG;
    }

    nvs_handle_t handle;
    esp_err_t error = nvs_open("settings", NVS_READWRITE, &handle);
    if (error != ESP_OK) {
        return error;
    }
    error = nvs_set_u32(handle, "period_ms", periodMs);
    if (error == ESP_OK) {
        error = nvs_commit(handle);
    }
    nvs_close(handle);
    return error;
}

esp_err_t loadSamplePeriod(uint32_t *periodMs)
{
    if (periodMs == NULL) {
        return ESP_ERR_INVALID_ARG;
    }

    nvs_handle_t handle;
    esp_err_t error = nvs_open("settings", NVS_READONLY, &handle);
    if (error != ESP_OK) {
        return error;
    }
    error = nvs_get_u32(handle, "period_ms", periodMs);
    nvs_close(handle);
    return error;
}
```

首次启动时命名空间或键不存在可能返回 `ESP_ERR_NVS_NOT_FOUND`，由应用决定默认值。`nvs_close()` 不替代提交，且一次成功读取也不免除对参数范围的业务校验。

## VFS、SPIFFS 与 SD 卡

VFS 统一应用的文件接口，通过挂载路径分发到底层文件系统。SPIFFS 常用于 Flash 上的小文件，不提供完整的目录语义；文件系统挂载、容量、写入放大与断电恢复均需考虑。

MicroSD 存储卡可通过 SDMMC 或 SPI 主机访问；SDIO I/O 设备与 SD 存储卡并非同一类设备。挂载 FAT 后应用可使用 `fopen()`、`fread()`、`fwrite()` 等接口，必须检查返回长度和关闭结果。挂载失败自动格式化可能破坏原数据，只能由明确的产品策略决定。

SDMMC 数据线宽度、上拉、引脚与 Flash 冲突由具体芯片和板级设计决定，不能直接复制参考板的 GPIO 表。

## ST7789 与 LVGL 数据流

显示链路为 LVGL 绘制缓冲区、刷新回调、LCD 总线接口与面板。SPI 总线传输速度、像素格式和刷新区域共同决定带宽；旋转、颜色顺序、偏移及背光由显示适配层配置。

原始资料基于 LVGL 8.3.10：用 `lv_disp_draw_buf_init()` 配置绘制缓冲区，初始化和注册 `lv_disp_drv_t`，设置分辨率及 `flush_cb`。异步 DMA 传输完成后才能调用 `lv_disp_flush_ready()`，不能在传输仍读取缓冲区时允许 LVGL 重用它。

双缓冲可以重叠绘制与传输；局部刷新缓冲不必等于整屏大小，但必须满足 DMA、内存区域和对齐约束。LVGL 的 Tick 来源与处理函数应有稳定时间基准，多任务访问按库与移植约定串行化。LVGL 9 的显示接口已变化，不能把 8 的结构体和 9 的函数混用。
