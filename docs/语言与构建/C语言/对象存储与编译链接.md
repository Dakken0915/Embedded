# 对象存储与编译链接

## 作用域、存储期与链接属性

作用域规定名字在源码中何处可见，存储期规定对象何时存在，链接属性决定不同声明是否指向同一个实体。三者相互关联，但不能混为一谈。

| 声明形式 | 存储期 | 链接与可见性 |
| --- | --- | --- |
| 块内普通变量 | 自动存储期 | 块作用域，无链接 |
| 块内 `static` 变量 | 静态存储期 | 块作用域，无链接 |
| 文件作用域普通变量 | 静态存储期 | 通常具有外部链接 |
| 文件作用域 `static` 变量或函数 | 变量为静态存储期 | 内部链接，限定于翻译单元 |
| `extern int counter;` | 引用已有对象 | 通常为外部链接的声明，不因此创建新定义 |

静态存储期对象在程序启动前初始化，未显式初始化时按类型零初始化。非零初值常放在 `.data`，零值或未初始化对象常放在 `.bss`；段布局由工具链与链接脚本决定，不能说所有 static 局部变量都位于 `.data`。C 的块内 static 初始化受静态初始化约束，不能套用 C++ 的首次执行动态初始化规则。

```c
/* counter.h */
#ifndef COUNTER_H
#define COUNTER_H
extern unsigned counter;
void incrementCounter(void);
#endif

/* counter.c，独立翻译单元 */
#include "counter.h"
unsigned counter = 0;
static unsigned localCount;
void incrementCounter(void)
{
    static unsigned calls;
    ++calls;
    ++localCount;
    ++counter;
}
```

头文件通常存放声明、类型和宏。直接在被多个翻译单元包含的头文件中定义外部链接对象，容易形成重复定义；头文件保护只能防止一个翻译单元内重复包含。文件作用域的 `int x;` 还是暂定定义，不能仅凭“没有初始化”断言它只是声明。

## volatile、const 与并发

`volatile` 要求编译器按照实现规定保留相应可观察访问，适用于硬件寄存器等特殊对象。它不保证复合操作原子性，不刷新 Cache，不提供线程间同步，也不能替代内存屏障。ISR 与普通代码共享的对象还需核对编译器、中断 ABI、访问宽度和竞态；一个 `volatile` 标志不能保证其关联缓冲区的发布顺序。

`const` 限制通过相应表达式修改对象；对象不一定放在 ROM。去掉限定后修改原本定义为 const 的对象属于未定义行为。修改通过 const 指针观察的、原本可写的对象则可由其他合法可写引用完成。

const 对象、可写对象的只读访问、强制转换与字符串字面量的区别，见 [C 语言基础语法考点](./C语言基础语法考点.md)。

## 编译阶段与目标兼容性

预处理处理包含、条件编译与宏；编译进行语法语义分析并生成目标表示；汇编生成机器指令与重定位信息；链接解析符号、安排段并完成重定位。实际工具链可将阶段合并。

```shell
cc -E source.c -o source.i
cc -S source.i -o source.s
cc -c source.s -o source.o
cc source.o -o application
nm source.o
readelf -h -S application
```

Windows 上的可执行文件不能仅通过烧写就变成 MCU 程序。ISA、ABI、指令扩展、运行库、映像格式、入口、地址布局和硬件环境都必须匹配。内联汇编也是编译器扩展，ARMCC 的 `__asm { ... }` 不能直接当作 GCC 或 AArch64 的通用语法。

## 链接与运行时初始化

静态链接将所需目标代码纳入输出映像；动态链接通过共享对象及动态加载器完成相应符号解析。动态库既可在启动时按依赖加载，也可通过 `dlopen()` 显式加载。共享库不意味着所有数据在进程间共享，可写全局数据通常仍是进程私有。

裸机复位入口设置栈与运行环境，将 `.data` 初值从非易失存储复制到 RAM，清零 `.bss`，执行必要的 C/C++ 运行库初始化后进入 `main()`。Linux 进程的 ELF 装载则由内核、动态加载器与运行库协作完成，不能沿用裸机逐字节搬运模型解释所有装载。

动态分配、堆栈边界、资源所有权与内存泄漏见 [内存管理](./内存管理.md)。
