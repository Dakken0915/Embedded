# C 语言内存管理

## 内存分布与存储期

### .text（代码段）

> 存储内容：程序机器指令代码。通常属性为可执行、不可写。
>
> 说明：裸机平台可以直接在 Flash 上运行，也可以在启动时拷贝到 RAM 中执行，由平台链接脚本决定。

### .rodata（只读数据段）

> 存储内容：字符串字面量、只读常量、常量查找表。
>
> 说明：段名由工具链决定；函数内部的 const 局部变量不一定存放在这里，有可能分配在栈上或者寄存器。

### .data（已初始化数据段）

> 存储内容：带有显式非 0 初始值的全局变量、static 静态变量（静态存储期可写数据）、static 局部变量。
>
> 说明：裸机启动时，启动代码会把 Flash 中保存的初始值拷贝到 RAM 中，整个程序生命周期有效。

### .bss（未初始化数据段）

> 存储内容：零初始化、没有显式初始化的全局变量、static 静态变量（静态存储期对象）、static 局部变量。
>
> 说明：ELF 镜像文件里面不会存放大量 0 字节，减小固件体积；但是程序运行时依然会占用 RAM，启动阶段统一清零，生命周期伴随整个程序。

### 栈（stack）

> 存储内容：函数调用帧、函数参数、局部自动变量、返回地址、返回数据、临时数据。
>
> 说明：进入函数时自动分配，函数退出自动释放；分配效率高，容量有限；局部变量也可能被编译器优化到寄存器甚至直接消除；C 语言标准不规定栈的增长方向。一般向低地址增长。

### 堆（heap）

> 存储内容：`malloc/calloc/realloc`动态申请的内存，频繁分配释放会带来内存碎片问题。
>
> 说明：由程序员手动申请、手动 free 释放；忘记释放会造成内存泄漏，程序结束后操作系统会回收；Linux 底层通过 brk、mmap 实现，malloc 申请的内存不一定在同一块连续区域。一般向高地址生长

### 内存映射段

> 存储内容：mmap 映射的文件、外设、匿名内存。
>
> 说明：依托操作系统虚拟内存管理，把物理地址、文件映射到进程虚拟地址空间，程序不需要关心底层物理布局。

### TLS（线程局部存储区）

> 存储内容：`_Thread_local`修饰的线程私有变量。
>
> 说明：同一个变量名，每个线程拥有独立的实例；生命周期是线程存储期；裸机 RTOS 需要框架单独提供 TLS 支持。



```c
#include <stddef.h>

int initialized = 7;              /* 常见实现：.data */
int zero_initialized;             /* 常见实现：.bss */
const int lookup_limit = 32;       /* 可能位于只读段 */
_Thread_local unsigned visits;    /* 每线程实例 */

size_t count_visit(void)
{
    static size_t calls;          /* 静态存储期，不是自动栈对象 */
    size_t previous = calls;     /* 自动存储期，不保证实际占栈 */
    ++calls;
    ++visits;
    return previous;
}
```



## 分配、初始化与释放接口

包含 `<stdlib.h>`，大小参数使用 `size_t`；动态分配接口不隐含构造函数或析构函数。

| 接口 | 语义 | 边界 |
| --- | --- | --- |
| `malloc(bytes)` | 申请指定字节数，未初始化 | 成功后须先写入再读取；失败返回 `NULL` |
| `calloc(count, size)` | 为数组分配空间并将所有位清零 | 字节清零不等于对任意类型完成语义初始化，例如不能普遍保证得到空指针或浮点零表示 |
| `realloc(p, bytes)` | 调整容量，保留新旧大小较小范围内的字节 | 可能搬迁；新增部分未初始化；非零大小失败时原对象仍有效 |
| `free(p)` | 结束对应分配的生命周期，交回分配器 | 只能传相应分配接口得到且尚未释放的起始指针，或 `NULL` |
| `aligned_alloc(alignment, size)` | C11 对齐分配 | 对齐值须受实现支持，大小须为对齐的整数倍；成功后按实现契约用 free 释放 |



## new 与 malloc 的区别

`new` 是 C++ 运算符，不能用于 C 源文件；这里从 C 动态分配接口出发比较两者。以下采用 C11 与 C++11 及后续标准的常用形式，超对齐分配另需满足所选标准和平台要求。

| 比较项 | C++ `new` 表达式 | `malloc` |
| --- | --- | --- |
| 语言与形式 | C++ 语言表达式，如 `new T(args)` | C 标准库函数；C++ 也可通过 `<cstdlib>` 使用 `std::malloc` |
| 大小与返回类型 | 根据类型计算空间，返回对应类型指针；数组还要提供元素数量 | 显式传入字节数，返回 `void*`，数组大小计算须防止乘法溢出 |
| 类型转换 | `new T` 返回 `T*` | C 中 `void*` 可隐式转换为对象指针，无须强制转换；C++ 中需要显式转换 |
| 对象初始化 | 获得存储后按语法初始化对象；类对象会调用所选构造函数 | 不调用 C++ 构造函数，也不初始化所分配字节，不可直接依赖其内容 |
| 分配失败 | 通常抛出 `std::bad_alloc`；标准 `new (std::nothrow)` 分配失败返回空指针 | 返回空指针，调用方必须检查 |
| 释放 | `new T` 对应 `delete`，`new T[n]` 对应 `delete[]`；类对象先析构再释放存储 | 对应 `free`；不调用 C++ 析构函数 |

`new int` 不会自动把整数置零，读取前仍须赋值；`new int{}` 将其初始化为零。`new int[n]` 的元素也不会自动清零，`new int[n]{}` 才进行值初始化。`malloc` 的未初始化内容应称为不确定值，不能以“未定义的内容”代替对读取行为的分析。

### 分配函数与构造过程

普通 `new T(args)` 可以理解为获得合适存储，再初始化 `T`。其中 `operator new` 是分配函数，负责存储；构造是 `new` 表达式的另一部分。标准不要求 `operator new` 必须调用 `malloc`，它可以被替换，也可能存在类专用分配函数。`malloc` 同样通常使用分配器管理已有空闲块，不保证每次都直接调用内核。语义依据见 [new 表达式](https://eel.is/c++draft/expr.new)、[operator new](https://eel.is/c++draft/new.delete.single) 与 [Linux malloc(3)](https://man7.org/linux/man-pages/man3/malloc.3.html)。

若普通 `new` 已取得存储但构造函数抛异常，会调用适用的匹配释放函数回收这次存储；构造函数内自行取得的其他资源仍须正确管理。`std::nothrow` 只改变分配失败的处理，不会吞掉构造函数抛出的异常。

定位 `new (address) T(args)` 在已有且大小、对齐合适的存储上构造对象，不负责另行分配存储。后续须分别处理对象析构与存储回收，不能因为使用了定位 new 就直接使用普通 `delete`。

### 对应的分配与释放示例

以下 C11 片段依赖 `<stdlib.h>`；函数将分配失败作为返回值交给调用方，初始化后再读写，并在所有成功路径释放存储。

```c
#include <stdlib.h>

int use_malloc(void)
{
    int *value = malloc(sizeof *value); /* C 中不需要强制转换 */
    if (value == NULL) {
        return -1;
    }
    *value = 42;
    int result = *value;
    free(value);
    return result;
}
```

下面是 C++11 完整示例，依赖标准库，采用带异常的普通 `new`。数组分配失败时先前创建的对象由 `unique_ptr` 回收；全部局部资源在离开作用域时析构。

```cpp
#include <memory>
#include <new>

struct Item {
    explicit Item(int initial) : value(initial) {}
    int value;
};

int main()
{
    try {
        std::unique_ptr<Item> item(new Item(42));
        std::unique_ptr<int[]> values(new int[4]{});
        values[0] = item->value;
        return values[0] == 42 && values[1] == 0 ? 0 : 1;
    } catch (const std::bad_alloc&) {
        return 1;
    }
}
```

`unique_ptr<Item>` 使用 `delete`，`unique_ptr<int[]>` 使用 `delete[]`。`malloc/free`、`new/delete`、`new[]/delete[]` 不得交叉配对，也不能用 `realloc` 调整一般 C++ 对象数组。C++20 的 `malloc` 可隐式开始部分隐式生命周期类型的生命周期，但仍不调用构造函数，不能据此直接使用任意带构造逻辑的类；见 [C++ C 分配接口](https://eel.is/c++draft/c.malloc)。



## 内存泄漏

1. 指针重新赋值，覆盖原有 malloc 地址，丢失释放入口

   ```C
   char *p = malloc(10);
   p = malloc(20);
   ```

2. 分支提前 return，跳过 free

   ```C
   char *p = malloc(100);
   if(flag) return;
   free(p);
   ```

3. 结构体嵌套堆内存，只 free 外层，内部 buf 没释放

   ```C
   struct T{ char *buf; };
   struct T *t = malloc(sizeof(*t));
   t->buf = malloc(100);
   free(t);
   ```

4. 循环里不断 malloc，循环内不 free

   ```C
   while(1) {
       char *p = malloc(10);
   }
   ```

**总结：1. 堆内存申请后，再也没有机会执行 free/delete。2. 指针重新赋值、改变指向**



## 野指针和空指针区别

> 悬空指针保存的地址曾经有效，但对应内存已经被回收需要置 NULL
>
> 野指针从未执行有效地址
