# 类与对象

## 定义、封装与访问控制

类将数据及操作封装为类型，对象是该类型的实例。public 提供公开接口，protected 允许类成员、友元及符合规则的派生类访问，private 限定为类成员与友元访问。成员函数可在类内定义，也可在命名空间作用域用 `ClassName::function` 定义。

C++ 的 struct 和 class 都支持构造析构、继承及虚函数；struct 默认成员及默认继承为 public，class 默认为 private。C 的结构体不具备这些成员函数和访问控制语义。

```cpp
class Counter {
public:
    explicit Counter(int initial = 0) : value_(initial) {}
    void increment();
    int value() const { return value_; }
private:
    int value_;
};
void Counter::increment()
{
    ++value_;
}
```

## 构造、成员初始化与析构

构造函数没有返回类型，可以重载。默认构造函数是能够不提供实参调用的构造函数，并非只能完全没有形参。成员初始化先于构造函数体；const 成员、引用成员及需要指定构造方式的成员应在初始化列表中初始化。

```cpp
class Measurement {
public:
    Measurement(int initial, const int& reference)
        : value_(initial), scale_(100), reference_(reference) {}
    int value() const { return value_; }
private:
    int value_;
    const int scale_;
    const int& reference_;
};
```

reference 所引用对象须比 Measurement 活得更久。不能像将按值形参 `int x` 绑定到成员引用那样，让引用在构造返回后悬空。

### 基类、成员与派生类的调用顺序

单继承、没有虚基类时，可概括为：构造先完成基类，再构造成员对象，最后执行派生类构造函数体；析构先执行派生类析构函数体，再销毁成员对象，最后销毁基类。这里的“最后子类”指构造函数体，派生类对象的构造过程本身包含前面的基类和成员初始化。

完整的非委托构造顺序为：

1. 最派生类负责初始化虚基类，顺序由继承图深度优先、从左到右的遍历决定，同一个虚基类子对象只初始化一次。
2. 按基类列表中的声明顺序初始化直接非虚基类。
3. 按类内声明顺序初始化非静态数据成员。
4. 执行当前类构造函数体。

初始化列表的书写顺序不能改变上述规则。销毁时先执行当前类析构函数体，再逆序销毁非静态成员和直接非虚基类；最派生对象最后销毁虚基类。成员和基类的具体销毁次序与构造次序相反，静态数据成员不参与每个实例的构造、析构链。规则见 [C++ 基类与成员初始化](https://eel.is/c++draft/class.base.init) 与 [析构函数](https://eel.is/c++draft/class.dtor)。

下面是 C++11 及后续标准的完整示例，仅依赖标准库。两个成员的顺序由 `first_`、`second_` 的声明决定；即使交换初始化列表中的书写位置，也不会交换实际构造顺序，编译器通常会对此产生告警。

```cpp
#include <iostream>

struct BasePart {
    BasePart() { std::cout << "Base\n"; }
    ~BasePart() { std::cout << "~Base\n"; }
};

struct MemberPart {
    explicit MemberPart(const char* name) : name_(name)
    {
        std::cout << name_ << '\n';
    }
    ~MemberPart() { std::cout << '~' << name_ << '\n'; }
private:
    const char* name_; // 本例指向具有静态存储期的字符串字面量
};

class DerivedPart : public BasePart {
public:
    DerivedPart() : first_("first"), second_("second")
    {
        std::cout << "Derived\n";
    }
    ~DerivedPart() { std::cout << "~Derived\n"; }
private:
    MemberPart first_;
    MemberPart second_;
};

int main()
{
    DerivedPart object; // 自动存储期，离开作用域时销毁
}
```

输出依次为 `Base → first → second → Derived → ~Derived → ~second → ~first → ~Base`。这里通过派生类对象本身销毁，没有通过基类指针删除，因此示例不要求基类具有虚析构函数。

若构造期间抛出异常，已完成构造的基类和成员会被逆序销毁，尚未完成构造的整个对象不会调用其析构函数。构造函数体中直接取得的裸资源仍可能泄漏，应交给成员 RAII 对象管理；相关所有权策略见 [浅拷贝与深拷贝](./浅拷贝与深拷贝.md)。

### 构造函数什么时候可以不写

没有用户声明的构造函数或构造函数模板时，编译器隐式声明一个无参默认构造函数；但它可能被定义为删除，不能保证一定可调用。只要用户声明了构造函数，包括带参、拷贝或移动构造函数，就不再自动补出这个无参构造函数。规则见 [默认构造函数](https://eel.is/c++draft/class.default.ctor)。

| 情况 | 默认构造的结果 |
| --- | --- |
| 不声明构造函数，基类和成员都能有效默认初始化 | 通常可以直接默认构造 |
| 只声明 `explicit T(int)`，参数没有默认实参 | 不能用 `T t;` 或 `T t{};`，可以按需另加 `T() = default` |
| 声明 `explicit T(int value = 0)` | 它本身就是可无实参调用的默认构造函数，无需再声明无参版本 |
| 引用成员没有默认成员初始化器，也没有构造初始化 | 隐式或显式 default 的默认构造函数被删除 |
| 基类或类类型成员缺少可用的默认构造方式 | 默认构造函数可能被删除；需要显式提供适当初始化 |
| 普通 `const int` 成员未提供初始化 | 不能依靠默认生成的构造函数补出有效初始化 |

`= default` 表示请求编译器按默认规则定义函数，不会绕过成员和基类的限制。C++11 起可使用默认成员初始化器，例如 `int value_ = 0;`，避免成员在默认初始化时保留不确定值；不能把“编译器生成构造函数”理解为“全部成员自动清零”。

下面是 C++11 完整示例，依赖 `<type_traits>`，以编译期断言检查默认构造能力，并在运行时检查初始化结果。

```cpp
#include <type_traits>

struct Automatic {
    int value = 0;
};
struct ArgumentOnly {
    explicit ArgumentOnly(int initial) : value(initial) {}
    int value;
};
struct Restored {
    Restored() = default;
    explicit Restored(int initial) : value(initial) {}
    int value = 0;
};
struct DefaultArgument {
    explicit DefaultArgument(int initial = 7) : value(initial) {}
    int value;
};
struct ReferenceMember {
    int& reference; // 缺少绑定对象，不能默认构造
};
struct NeedsArgument {
    ArgumentOnly member; // member 没有默认构造函数
};

static_assert(std::is_default_constructible<Automatic>::value, "automatic");
static_assert(!std::is_default_constructible<ArgumentOnly>::value, "argument");
static_assert(std::is_default_constructible<Restored>::value, "restored");
static_assert(std::is_default_constructible<DefaultArgument>::value, "default arg");
static_assert(!std::is_default_constructible<ReferenceMember>::value, "reference");
static_assert(!std::is_default_constructible<NeedsArgument>::value, "member");

int main()
{
    Automatic automatic;
    Restored restored;
    DefaultArgument supplied;
    return automatic.value == 0 && restored.value == 0 && supplied.value == 7
               ? 0 : 1;
}
```

析构函数也可以不写，成员为标准容器或智能指针时，隐式析构会依次销毁成员。若类直接拥有必须手动释放的资源，就需要明确析构与拷贝、移动策略。普通析构函数没有形参和返回类型，不能以不同参数重载；隐式拷贝、移动、赋值和析构的生成、删除或抑制各有条件，不能说空类一定拥有六个可调用的默认函数。C++17 还存在强制复制消除，返回临时对象不一定调用移动构造。

## 拷贝、移动与所有权

编译器生成的拷贝按基类与成员各自的拷贝语义进行。裸指针成员只复制地址，不会自动复制其所指向的资源；拥有资源的类需要明确独占、共享或独立复制策略。`std::string`、`std::vector` 等成员可以让外层对象直接采用值语义。

## 继承及对象中的基类部分

public 继承保持基类 public/protected 的相应可访问性；protected 继承将它们作为派生类 protected 接口，private 继承将它们作为 private 接口。基类 private 成员仍存在于基类子对象中，但不会因继承方式变化而自动对派生类开放。

派生类可添加成员、重写虚函数，也可发生名字隐藏。构造派生类时必须构造基类；未指定基类初始化器时，要求相应默认初始化有效。多继承涉及多个基类子对象，虚继承用于共享虚基类，不等同于虚函数。

## 虚函数、纯虚函数与析构

通过基类指针或引用调用虚函数时，按动态类型选择最终重写者；`override` 帮助检查签名。纯虚函数以 `= 0` 声明，使类在相应条件下为抽象类；纯虚函数也可以具有定义，不能一概说只有声明。

### 构造函数不能是虚函数

构造函数不能声明为 `virtual`，也没有“虚构造函数”供派生类重写。创建对象时，构造目标类型由 `Derived(...)`、`new Derived(...)` 或工厂内部的具体构造表达式确定；需要运行时选择具体类型时，可以使用返回基类智能指针的工厂。

构造和析构期间可以调用普通虚成员函数，但虚调用只分派到当前正在构造或析构的类及其基类，不会进入尚未构造或已经销毁的更派生部分。在构造或析构期间，对正在构造或销毁的对象直接或间接进行纯虚函数的虚调用属于未定义行为；不要依赖虚调用完成派生资源初始化或清理。

### 虚析构保证通过基类接口销毁完整对象

如果对象需要通过基类指针执行普通单对象 `delete`，基类应提供可访问的虚析构函数。即使基类没有其他虚函数，这个要求仍然成立；只有普通虚成员函数而没有虚析构也不能保证安全删除。基类析构是虚函数时，派生类析构自动也是虚函数，可写 `override` 让编译器检查。

下面是 C++11 完整示例，依赖标准库，保留独占数组来展示资源清理；删除拷贝操作以避免裸指针的浅拷贝导致重复释放。分配异常由 `main` 捕获，成功分配的数组在派生类析构中释放。

```cpp
#include <iostream>
#include <new>

class Base {
public:
    virtual ~Base() { std::cout << "~Base\n"; }
};

class Derived final : public Base {
public:
    Derived() : data_(new int[100]{}) {}
    Derived(const Derived&) = delete;
    Derived& operator=(const Derived&) = delete;
    ~Derived() override
    {
        delete[] data_;
        std::cout << "~Derived\n";
    }
private:
    int* data_;
};

int main()
{
    try {
        Base* object = new Derived;
        delete object;
    } catch (const std::bad_alloc&) {
        return 1;
    }
}
```

正常输出为 `~Derived → ~Base`，数组在 `~Derived` 中释放。若去掉基类析构的 `virtual`，并相应去掉派生析构的 `override`，再经 `Base*` 删除 `Derived`，在这里采用的 C++11/14 普通删除语义下属于未定义行为。不能将结果限定为“只执行基类析构、必然泄漏”，也不应实际运行它来推断语言保证。[delete 表达式规则](https://eel.is/c++draft/expr.delete)

不需要通过基类删除的类型可以使用受保护的非虚析构函数，阻止外部代码执行 `delete basePointer`；不参与此类继承接口的普通值类型也无需一律增加虚析构。`std::unique_ptr<Base>` 的默认删除器仍通过 `Base*` 删除，不能修复基类缺少虚析构的问题。虚析构也不能使 `Base* p = new Derived[n]; delete[] p;` 合法，数组必须按正确元素类型与分配方式释放。

### 纯虚析构使基类保持抽象

`virtual ~Base() = 0;` 同时保留虚析构语义并使基类成为抽象类，适合没有其他纯虚操作、但仍要禁止直接实例化的接口基类。纯虚声明并不取消基类析构工作：销毁派生对象仍须销毁其基类部分，因此实际创建并销毁派生对象的程序必须提供基类析构定义。

定义放在类外，例如 `Base::~Base() = default;`，不能把 `= 0` 和函数体写在同一个声明上。若定义放在由多个翻译单元包含的头文件中，应使用 `inline` 或把定义移到单个 `.cpp`，避免重复定义。规则见 [抽象类](https://eel.is/c++draft/class.abstract)。

以下 C++11 完整示例依赖标准库。`Sensor` 不能实例化；`FixedSensor` 实现其他纯虚操作并具有自己的析构最终重写者，因此可以实例化。即使省略 `FixedSensor` 中显式书写的析构函数，隐式析构也会重写基类虚析构，不要求派生类一定手写析构。

```cpp
#include <iostream>
#include <memory>
#include <type_traits>
class Sensor {
public:
    virtual ~Sensor() = 0;
    virtual int read() const = 0;
};
Sensor::~Sensor() { std::cout << "~Sensor\n"; }
class FixedSensor final : public Sensor {
public:
    ~FixedSensor() override { std::cout << "~FixedSensor\n"; }
    int read() const override { return 25; }
};
static_assert(std::is_abstract<Sensor>::value, "abstract base");
static_assert(!std::is_abstract<FixedSensor>::value, "concrete derived");
int main()
{
    std::unique_ptr<Sensor> sensor(new FixedSensor);
    return sensor->read() == 25 ? 0 : 1;
}
```

离开 `main` 时，智能指针先调用 `~FixedSensor`，再调用 `~Sensor`。若只保留纯虚析构声明而缺少定义，实际销毁派生对象时常见结果是链接器报告基类析构符号未定义；“纯虚”不意味着基类部分无需析构。反过来，非纯虚析构也可写成 `virtual ~Base() = default;`，并非必须手写函数体。

vtable/vptr 是常见 ABI 实现方式，标准并不要求每个对象的首地址只有一个 vptr，也不固定表的数量或存储段。多继承、虚继承和构造阶段都会使布局更复杂。构造期间的虚调用不会分派到尚未构造完成的更派生部分；构造函数本身不能声明为 virtual。静态成员函数没有 this，不能为 virtual；虚函数可声明 inline，但实际展开不受保证。

## 运算符重载

重载为用户类型定义现有运算符的行为，不能改变运算符优先级或操作数个数，也不能创建新运算符。算术、比较、赋值、位运算、调用、下标、解引用及 new/delete 等具有各自重载规则。

```cpp
struct Box {
    double length, width, height;
    Box operator+(const Box& other) const
    {
        return {length + other.length, width + other.width,
                height + other.height};
    }
    double volume() const { return length * width * height; }
};
```

这里的加法定义为三维尺寸逐项相加，只是一种类型设计约定。`.`、`.*`、`::`、`?:`、`sizeof` 等不能重载；`->*` 可以重载，不能和 `.*` 混淆。重载 `&&`、`||` 不保留内置运算符的短路语义。

## explicit、const 与 this

`explicit` 限制相应构造函数参与隐式转换，也可用于转换函数；并不只适用于单形参构造函数，也不等于禁止所有拷贝构造。`this` 是非静态成员函数中的对象指针，const 成员函数中不能通过它修改普通数据成员；mutable 成员可例外修改，但线程安全仍需单独保证。
