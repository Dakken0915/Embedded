# 类与对象

## 定义、封装与访问控制

类将数据及操作封装为类型，对象是该类型的实例。public 提供公开接口，protected 允许类成员、友元及符合规则的派生类访问，private 限定为类成员与友元访问。成员函数可在类内定义，也可在命名空间作用域用 `ClassName::function` 定义。

C++ 的 struct 和 class 都支持构造析构、继承及虚函数；struct 默认成员及默认继承为 public，class 默认为 private。C 的结构体不具备这些成员函数和访问控制语义。

```cpp
class Counter {
public:
    explicit Counter(int initial = 0) : value_(initial) {}
    void increment();
    int value() const { return value_; }
private:
    int value_;
};
void Counter::increment()
{
    ++value_;
}
```

## 构造、成员初始化与析构

构造函数没有返回类型，可以重载。默认构造函数是能够不提供实参调用的构造函数，并非只能完全没有形参。成员初始化先于构造函数体；const 成员、引用成员及需要指定构造方式的成员应在初始化列表中初始化。

```cpp
class Measurement {
public:
    Measurement(int initial, const int& reference)
        : value_(initial), scale_(100), reference_(reference) {}
    int value() const { return value_; }
private:
    int value_;
    const int scale_;
    const int& reference_;
};
```

reference 所引用对象须比 Measurement 活得更久。不能像将按值形参 `int x` 绑定到成员引用那样，让引用在构造返回后悬空。

构造顺序为虚基类、直接基类、按声明顺序排列的非静态成员，最后执行构造函数体；初始化列表的书写顺序不能改变此规则。析构先执行当前类析构函数体，再逆序销毁成员和相应基类。析构函数没有形参和返回类型，不能以不同参数重载。

未提供用户声明构造函数时，编译器可隐式声明默认构造函数；是否可用还取决于成员和基类。隐式拷贝、移动、赋值和析构的生成、删除或抑制都有条件，不能说空类一定拥有六个可调用的默认函数。C++17 还存在强制复制消除，返回临时对象不一定调用移动构造。

## 拷贝、移动与所有权

### 浅拷贝与深拷贝

浅拷贝复制指针或句柄等成员，使副本继续访问同一份外部资源；深拷贝为需要独立拥有的资源创建副本，使两个对象可以分别修改、分别销毁。深浅描述的是资源复制策略，C++ 没有专门执行“深拷贝”的关键字。对于含有指针、共享节点或环的复杂结构，还必须明确哪些资源需要复制、哪些资源继续共享，不能机械地递归复制所有指针。

编译器生成或显式 `= default` 的拷贝操作按基类和成员各自的拷贝语义执行，并不一概等于浅拷贝。

| 成员类型 | 默认拷贝的结果 | 所有权和限制 |
| --- | --- | --- |
| `int` 等普通值、内置数组 | 复制值；数组逐元素复制 | 对副本的元素修改不改变原对象元素 |
| `T*` 裸指针 | 复制地址，不复制所指对象 | 非拥有指针可以有意共享；拥有指针需要另外设计复制和释放策略 |
| `std::string`、`std::vector<int>` | 复制内容，两个对象可独立修改 | 优先用这类成员表达值语义 |
| `std::vector<T*>` | 复制容器中的指针值 | 容器独立，但所指对象仍共享，容器也不会自动 `delete` 这些对象 |
| `std::shared_ptr<T>` | 共享同一所有权组，不克隆所指对象 | 通常共同管理同一对象；引用计数不保护对象内容的并发访问 |
| `std::unique_ptr<T>` | 不允许拷贝 | 含有它的类默认拷贝通常被删除；需要独立副本时显式实现克隆，或只允许移动 |

下面是合法的浅拷贝：`IntView` 只观察外部整数，不负责释放它。示例适用于 C++14 及以上，只依赖标准库；被引用整数的生命周期必须覆盖所有视图访问。

```cpp
#include <cassert>

struct IntView {
    int* value; // 非拥有指针，不在析构函数中 delete
};

int main()
{
    int number = 10;
    IntView first{&number};
    IntView second = first;
    assert(first.value == second.value);
    *second.value = 20;
    assert(*first.value == 20);
}
```

如果类改为拥有 `new[]` 得到的内存，并在析构时 `delete[]`，默认拷贝构造会让两个对象认为自己拥有同一地址，导致悬空访问和重复释放。默认拷贝赋值还可能直接覆盖目标原来的指针，泄漏原资源。仅补一个析构函数或拷贝构造函数不能解决全部问题。`memcpy` 也不能替代对象的拷贝操作；对非平凡可复制类型直接按字节复制，不能建立其要求的对象和资源语义。

### 拷贝构造与拷贝赋值

| 表达式 | 对象状态 | 调用的操作 |
| --- | --- | --- |
| `Buffer b = a;` 或 `Buffer b(a);` | 创建新对象 `b` | 拷贝构造 `Buffer(const Buffer&)`，其中 `a` 是同类型左值 |
| `b = a;` | `b` 已存在 | 拷贝赋值 `Buffer& operator=(const Buffer&)` |
| `Buffer b = std::move(a);` | 创建新对象 `b` | 若存在可用的移动构造，通常选择它；否则可能回退到接受 const 引用的拷贝构造 |

初始化中的 `=` 不表示拷贝赋值。常见拷贝构造参数为 `const T&`，既避免再复制形参，又允许复制 const 对象；写成单个按值参数 `T(T)` 的构造函数不合法。拷贝赋值必须同时处理目标已有资源、自赋值以及分配失败，通常返回 `*this` 的引用以支持连续赋值。

### 独占缓冲区的深拷贝实现

下面用裸指针展示资源管理过程；实际业务可优先使用后文的 `std::vector` 版本。示例适用于 C++14 及以上，只依赖标准库，存储字节数据；分配失败由 `new[]` 抛出异常，越界访问抛出 `std::out_of_range`，对象不提供并发修改保护。

```cpp
#include <algorithm>
#include <cassert>
#include <cstddef>
#include <cstdint>
#include <stdexcept>
#include <utility>

class Buffer {
public:
    explicit Buffer(std::size_t size = 0)
        : size_(size), data_(size ? new std::uint8_t[size]{} : nullptr) {}

    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& other) : Buffer(other.size_)
    {
        if (size_ != 0) {
            std::copy_n(other.data_, size_, data_);
        }
    }

    Buffer& operator=(const Buffer& other)
    {
        if (this != &other) {
            Buffer temporary(other); // 分配失败时，当前对象保持原状
            swap(temporary);         // 临时对象随后释放当前对象原来的内存
        }
        return *this;
    }

    Buffer(Buffer&& other) noexcept
        : size_(std::exchange(other.size_, 0)),
          data_(std::exchange(other.data_, nullptr)) {}

    Buffer& operator=(Buffer&& other) noexcept
    {
        if (this != &other) {
            delete[] data_;
            size_ = std::exchange(other.size_, 0);
            data_ = std::exchange(other.data_, nullptr);
        }
        return *this;
    }

    void swap(Buffer& other) noexcept
    {
        std::swap(size_, other.size_);
        std::swap(data_, other.data_);
    }

    std::size_t size() const noexcept { return size_; }
    const std::uint8_t* data() const noexcept { return data_; }

    std::uint8_t& at(std::size_t index)
    {
        if (index >= size_) {
            throw std::out_of_range("Buffer::at");
        }
        return data_[index];
    }

    const std::uint8_t& at(std::size_t index) const
    {
        if (index >= size_) {
            throw std::out_of_range("Buffer::at");
        }
        return data_[index];
    }

private:
    std::size_t size_;
    std::uint8_t* data_;
};

int main()
{
    Buffer original(4);
    original.at(0) = 42;
    Buffer copied = original; // 拷贝构造：申请独立内存
    assert(copied.data() != original.data());
    copied.at(0) = 7;
    assert(original.at(0) == 42);

    Buffer assigned(2);
    assigned = original; // 拷贝赋值：替换并释放原有资源
    assert(assigned.size() == 4 && assigned.at(0) == 42);
    assert(assigned.data() != original.data());
    Buffer& same = assigned;
    assigned = same; // 自拷贝赋值仍保持原值
    assert(assigned.at(0) == 42);

    Buffer empty;
    Buffer empty_copy(empty);
    assert(empty_copy.size() == 0 && empty_copy.data() == nullptr);
    assigned = empty;
    assert(assigned.size() == 0 && assigned.data() == nullptr);

    const auto* storage = copied.data();
    Buffer moved(std::move(copied));
    assert(moved.data() == storage && moved.at(0) == 7);
    assert(copied.size() == 0 && copied.data() == nullptr);
    Buffer destination(3);
    destination = std::move(moved);
    assert(destination.data() == storage && moved.size() == 0);
    Buffer& self = destination;
    destination = std::move(self); // 本实现允许自移动赋值
    assert(destination.at(0) == 7);

    bool rejected = false;
    try {
        empty.at(0);
    } catch (const std::out_of_range&) {
        rejected = true;
    }
    assert(rejected);
}
```

拷贝构造的耗时和额外存储与字节数成正比。拷贝赋值先构造副本，再执行不会抛异常的交换，即 copy-and-swap；若分配失败，目标原值保持不变，满足强异常保证。这里复制的是不会抛异常的字节元素；若改为复制可能抛异常的复杂对象，需要重新检查构造期间的资源清理。

移动操作转交原指针，不分配另一份缓冲区，因此不属于深拷贝。本实现主动将被移动源置为空，且自身移动赋值保持原值；这些是 `Buffer` 的具体约定。单纯把裸指针成员的移动函数写成 `= default` 只会复制指针值，不会自动清空源指针，仍可能重复释放。`std::move` 本身只是转换为允许移动的值类别，不负责转交资源；具名右值引用表达式仍是左值。

### 三法则、五法则与零法则

| 规则 | 含义 |
| --- | --- |
| 三法则（Rule of Three） | 手工管理资源而需要自定义析构、拷贝构造、拷贝赋值中的一个时，通常需要统一考虑三者 |
| 五法则（Rule of Five，C++11 起） | 在三者基础上，同时考虑移动构造和移动赋值；某些操作可以明确 `= delete` |
| 零法则（Rule of Zero） | 让标准容器和 RAII 类型承担资源管理，外层类通常无需自定义这五个函数 |

用户声明析构函数会抑制隐式移动操作的生成；没有移动函数不一定导致右值初始化报错，因为它可能调用拷贝构造。是否支持拷贝应由类型语义决定：文件、互斥量或设备独占句柄通常禁止拷贝；共享所有权可使用 `shared_ptr`，需要独立内容副本时则提供明确的拷贝或克隆接口。

以下 C++14 示例用标准容器表达资源所有权，默认拷贝得到独立缓冲区，避免手工维护五个特殊成员函数。

```cpp
#include <cstddef>
#include <cstdint>
#include <utility>
#include <vector>
class Frame {
public:
    explicit Frame(std::size_t size) : pixels_(size) {}
    std::size_t size() const { return pixels_.size(); }
    std::uint8_t& at(std::size_t index) { return pixels_.at(index); }
private:
    std::vector<std::uint8_t> pixels_;
};
int main()
{
    Frame original(8);
    original.at(0) = 42;
    Frame copied = original;
    copied.at(0) = 7;
    Frame moved = std::move(copied);
    return original.at(0) == 42 && moved.at(0) == 7 ? 0 : 1;
}
```

移动后的标准库对象通常仍有效，但状态未指定，除非该类型有更具体保证。需要手工管理裸资源时，应统一考虑拷贝构造、拷贝赋值、移动构造、移动赋值及析构；使用 RAII 成员时优先遵循 Rule of Zero。

接口规则参见 C++ 标准草案的[拷贝与移动构造函数](https://eel.is/c++draft/class.copy.ctor)、[拷贝与移动赋值运算符](https://eel.is/c++draft/class.copy.assign)；共享指针的复制语义参见 [`shared_ptr` 构造](https://eel.is/c++draft/util.smartptr.shared.const)。

## 继承及对象中的基类部分

public 继承保持基类 public/protected 的相应可访问性；protected 继承将它们作为派生类 protected 接口，private 继承将它们作为 private 接口。基类 private 成员仍存在于基类子对象中，但不会因继承方式变化而自动对派生类开放。

派生类可添加成员、重写虚函数，也可发生名字隐藏。构造派生类时必须构造基类；未指定基类初始化器时，要求相应默认初始化有效。多继承涉及多个基类子对象，虚继承用于共享虚基类，不等同于虚函数。

## 虚函数、纯虚函数与析构

通过基类指针或引用调用虚函数时，按动态类型选择最终重写者；`override` 帮助检查签名。纯虚函数以 `= 0` 声明，使类在相应条件下为抽象类；纯虚函数也可以具有定义，不能一概说只有声明。

```cpp
#include <memory>
class Sensor {
public:
    virtual ~Sensor() = 0;
    virtual int read() const = 0;
};
Sensor::~Sensor() = default;
class FixedSensor final : public Sensor {
public:
    int read() const override { return 25; }
};
int main()
{
    std::unique_ptr<Sensor> sensor(new FixedSensor);
    return sensor->read() == 25 ? 0 : 1;
}
```

纯虚析构函数也必须有定义，因为派生对象销毁时仍需销毁基类部分。经通常的基类指针 delete 派生对象时，基类析构应为虚函数，否则可能构成未定义行为，不只是“只执行基类析构”。不支持通过基类删除的接口也可采用受保护非虚析构策略。

vtable/vptr 是常见 ABI 实现方式，标准并不要求每个对象的首地址只有一个 vptr，也不固定表的数量或存储段。多继承、虚继承和构造阶段都会使布局更复杂。构造期间的虚调用不会分派到尚未构造完成的更派生部分；构造函数本身不能声明为 virtual。静态成员函数没有 this，不能为 virtual；虚函数可声明 inline，但实际展开不受保证。

## 运算符重载

重载为用户类型定义现有运算符的行为，不能改变运算符优先级或操作数个数，也不能创建新运算符。算术、比较、赋值、位运算、调用、下标、解引用及 new/delete 等具有各自重载规则。

```cpp
struct Box {
    double length, width, height;
    Box operator+(const Box& other) const
    {
        return {length + other.length, width + other.width,
                height + other.height};
    }
    double volume() const { return length * width * height; }
};
```

这里的加法定义为三维尺寸逐项相加，只是一种类型设计约定。`.`、`.*`、`::`、`?:`、`sizeof` 等不能重载；`->*` 可以重载，不能和 `.*` 混淆。重载 `&&`、`||` 不保留内置运算符的短路语义。

## explicit、const 与 this

`explicit` 限制相应构造函数参与隐式转换，也可用于转换函数；并不只适用于单形参构造函数，也不等于禁止所有拷贝构造。`this` 是非静态成员函数中的对象指针，const 成员函数中不能通过它修改普通数据成员；mutable 成员可例外修改，但线程安全仍需单独保证。
