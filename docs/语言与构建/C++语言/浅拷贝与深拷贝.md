# 浅拷贝与深拷贝

<u>**浅拷贝（Shallow Copy）**</u>

> 只拷贝变量本身的值；如果里面包含指针，只复制指针地址，不复制指针指向的那块内存。
>
> 新对象和原对象里的指针指向同一块堆内存。

<u>**深拷贝（Deep Copy）**</u>

> 不仅拷贝变量本身，指针指向的堆内存也单独申请一份、把内容复制过去。
>
> 两个对象的指针指向两块独立内存，互不干扰。

## 为什么会发生浅拷贝

指针变量和指针指向的对象是两个独立的对象。`char* data` 保存的是地址，字符串字符存放在另一块存储中。默认拷贝复制 `data` 成员的值，得到的仍是原地址；编译器不会据此推断缓冲区长度、所有权、释放方式并重新分配字符串。

对于普通非联合类，准确说法是**按基类和成员执行拷贝**，不能笼统称为“默认按位拷贝”。成员是裸指针时复制地址，成员是 `std::string` 时调用字符串的复制语义。某些平凡类型的复制可被实现为字节搬运，但这不是所有 C++ 类的通用规则。

```text
浅拷贝：a.data ─┐
               ├──→ 同一块字符缓冲区
        b.data ─┘

深拷贝：a.data ───→ 原字符缓冲区
        b.data ───→ 新字符缓冲区（初始内容相同）
```

浅拷贝后，**通过指针修改共享缓冲区内容**会被另一对象观察到；只给 `b.data` 重新赋一个地址，并不会自动改变 `a.data` 的值。深拷贝为设计上需要独立拥有的资源创建副本，修改其中一份不影响另一份。



## 浅拷贝：共享内容与重复释放

```cpp
#include <cstring>
#include <iostream>

class Shallow {
public:
    char* data;

    explicit Shallow(const char* s)
        : data(new char[std::strlen(s) + 1])
    {
        std::strcpy(data, s);
    }

    ~Shallow() { delete[] data; }
    // 缺少拷贝构造和拷贝赋值：默认拷贝只复制 data 的地址。
};

int main()
{
    Shallow a("hello");
    Shallow b = a;
    std::cout << "地址: " << static_cast<const void*>(a.data)
              << " vs " << static_cast<const void*>(b.data) << std::endl;
    std::strcpy(b.data, "world"); // 与 hello 等长，当前容量足够
    std::cout << "改 b 后 a = " << a.data << std::endl;
    return 0; // b 先释放，a 再次释放同一分配：未定义行为
}
```

`Shallow b = a` 创建的是新的 `Shallow` 对象，两个指针成员本身也位于不同对象中，但它们保存的地址相同。问题不是“对象根本没复制”，而是资源没有复制，两个析构函数却都认为自己有释放权。若执行 `b = a`，默认赋值还可能覆盖 b 原来独占的地址，使那份原资源泄漏。

析构释放顺序不是修复办法；只删除析构中的 `delete[]` 会造成泄漏，只把某一个指针置空也不能表达普遍有效的所有权策略。若类只借用外部数据，则可以有意浅拷贝，但不得释放外部所有者的资源。



## 深拷贝：构造、赋值与安全修改

```cpp
#include <cassert>
#include <cstring>
#include <iostream>
#include <limits>
#include <stdexcept>
#include <utility>

class Deep {
public:
    explicit Deep(const char* s) : data_(duplicate(s)) {}

    Deep(const Deep& other) : data_(duplicate(other.data_)) {}

    Deep& operator=(const Deep& other)
    {
        if (this != &other) {
            Deep temporary(other);
            swap(temporary); // 临时对象销毁时释放本对象原有的缓冲区
        }
        return *this;
    }

    ~Deep() { delete[] data_; }

    void set(const char* s)
    {
        char* replacement = duplicate(s); // 失败时保留原值
        delete[] data_;
        data_ = replacement;
    }

    const char* get() const noexcept { return data_; }

    void swap(Deep& other) noexcept { std::swap(data_, other.data_); }

private:
    static char* duplicate(const char* s)
    {
        if (s == nullptr)
            throw std::invalid_argument("null string");
        const std::size_t length = std::strlen(s);
        if (length == std::numeric_limits<std::size_t>::max())
            throw std::length_error("string too long");
        char* result = new char[length + 1];
        std::memcpy(result, s, length + 1);
        return result;
    }

    char* data_;
};

int main()
{
    Deep a("hello");
    Deep b = a; // 拷贝构造，申请独立缓冲区
    assert(a.get() != b.get());
    std::cout << "地址: " << static_cast<const void*>(a.get())
              << " vs " << static_cast<const void*>(b.get()) << '\n';
    b.set("a longer string");
    assert(std::strcmp(a.get(), "hello") == 0);
    std::cout << "改 b 后 a = " << a.get() << '\n';

    Deep c("old");
    c = a; // 拷贝赋值，同样需要独立缓冲区
    assert(c.get() != a.get());
    Deep& alias = c;
    c = alias; // 自赋值
    c.set(c.get() + 1); // 输入借用自身存储，先复制再释放
    assert(std::strcmp(c.get(), "ello") == 0);
    b.set("");
    assert(b.get()[0] == '\0');
}
```

原例若只有 `Deep(const Deep&)` 而没有拷贝赋值，则 `Deep b = a` 安全并不能保证 `b = a` 也安全。直接 `strcpy(data, s)` 的 `set` 还要求新字符串不超出原容量且源目标不重叠；重新分配消除了这两个特定限制。`get` 返回借用地址，不能由调用者释放，且 `set`、赋值或对象销毁会使旧借用失效。

这里拷贝赋值采用 copy-and-swap，分配失败时目标不变；`set` 也在分配成功后才替换原资源。该类没有定义移动操作，右值可能回退到拷贝；下文 `Buffer` 展示完整五法则，实际字符串业务则优先用 `std::string`。



## 智能指针解决浅拷贝问题

### std::unique_ptr（独占式智能指针）

方案：禁止拷贝，只允许移动

- 把拷贝构造、拷贝赋值函数 delete 掉，不让你发生拷贝（直接杜绝浅拷贝场景）
- 只能 `std::move` 转移所有权，转移后原指针置空，只有一个 unique_ptr 持有这块内存

```C
unique_ptr<int> p1(new int(10));
// unique_ptr<int> p2 = p1;    // 编译报错，禁止拷贝
unique_ptr<int> p2 = move(p1); // 移动，所有权交给p2，p1变成空
```

> 原理：不允许多个对象持有同一个资源，从根源避免多析构。

### std::shared_ptr

方案：引用计数（reference count），不是深拷贝！

- 堆上除了用户资源，额外开辟一块控制块，里面存引用计数
- 拷贝 shared_ptr 的时候：
  1. 浅复制内部裸指针（指向同一块资源）
  2. 控制块里引用计数 +1
- 析构的时候：先把引用计数 - 1；计数减到 0 的时候，才真正 delete 释放堆内存

```C
shared_ptr<int> p1(new int(10));
shared_ptr<int> p2 = p1; // 拷贝，浅复制指针，计数从1→2
// p1、p2销毁时，计数依次减1；最后一个销毁时才释放内存
```

`shared_ptr`本身依旧是浅拷贝指针，它没有复制资源内容！只是靠计数控制什么时候释放，避免重复释放。
