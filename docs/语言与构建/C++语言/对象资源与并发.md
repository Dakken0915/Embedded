## C++ 语言语义要点



**const 成员函数**

- const 成员函数内，不能修改普通成员变量
- const 成员函数只能调用 const 成员函数，不能调用普通（非 const）成员函数
- 普通对象：既可以调用普通成员函数，也可以调用 const 成员函数
- const 对象 /const 引用 /const 指针：只能调用 const 成员函数
- `mutable` 修饰成员变量，可以在 const 成员函数中修改



静态成员函数不能声明为虚函数：静态成员函数属于类而不是对象，编译时就确定了地址

虚函数可以声明为 inline；inline 不保证调用处展开，是否去虚拟化和内联由具体调用信息及编译器决定。

构造函数不能声明为虚函数；构造阶段的虚调用遵循当前正在构造的类层次，不能分派到尚未构造的更派生部分。 


## 对象资源与并发语义

默认拷贝按成员的拷贝语义进行。裸指针成员通常只复制地址，不复制其所指向资源；两个对象若都释放同一资源，会造成重复释放。拥有独占资源的类需要定义完整的拷贝、移动和析构策略，或直接使用 `std::string`、`std::vector`、`std::unique_ptr` 等管理资源。仅补充拷贝构造而遗漏拷贝赋值仍不完整。

浅拷贝保留资源共享关系，深拷贝为需要独立拥有的资源创建副本。`std::vector<int>` 的默认拷贝可独立修改元素，但 `std::vector<int*>` 仍共享所指对象；`shared_ptr` 的复制也不会克隆对象。区别、拷贝构造与赋值接口、异常安全和完整缓冲区示例见[类与对象：浅拷贝与深拷贝](./类与对象.md#浅拷贝与深拷贝)。

对象构造按虚基类、直接基类、成员声明顺序和构造函数体的规则进行；成员初始化列表书写顺序不能改变成员声明顺序。析构时依相反的相关顺序清理。

不同 `shared_ptr` 实例共享控制块时，引用计数管理允许相应的并发操作，但不使所指对象自动线程安全。并发修改同一个 `shared_ptr` 变量仍需要同步或使用适用的原子接口；对象字段的并发访问需要独立保护。

`volatile` 表达具有特殊可观察访问语义的对象访问，不提供线程间原子性或内存同步。`std::atomic` 提供指定内存序的原子操作；互斥量用于保护更复杂的不变量和资源访问。多核环境下不能仅靠关闭本核心中断保护其他核心的访问。

## 智能指针的完整语义

unique_ptr 表达独占所有权，可移动而不可复制；shared_ptr 的控制块管理共享所有权；weak_ptr 不增加强引用计数，可用于打断共享所有权环，通过 lock 尝试取得有效 shared_ptr。智能指针对象本身既可位于栈，也可作为成员、静态对象或其他动态对象的一部分，不能说它只能在栈上。

new 分配并构造对象，delete 销毁并释放；new[] 与 delete[] 必须匹配。malloc 只取得原始存储，不构造 C++ 对象；定位 new 在已有适当大小和对齐的存储中构造对象，之后仍须匹配销毁与存储释放策略。

## 互斥量与条件变量

条件变量等待必须检查谓词，以处理虚假唤醒和竞争；谓词状态与等待使用同一互斥量保护。以下 C++14 示例中，一个线程发布值，另一个等待该值，线程退出前被 join。

```cpp
#include <condition_variable>
#include <mutex>
#include <thread>
int main()
{
    std::mutex mutex;
    std::condition_variable condition;
    bool ready = false;
    int result = 0;
    std::thread producer([&] {
        {
            std::lock_guard<std::mutex> guard(mutex);
            result = 42;
            ready = true;
        }
        condition.notify_one();
    });
    {
        std::unique_lock<std::mutex> lock(mutex);
        condition.wait(lock, [&] { return ready; });
    }
    producer.join();
    return result == 42 ? 0 : 1;
}
```

死锁的典型条件包括互斥、占有且等待、不可剥夺和循环等待。统一锁顺序、减少持锁范围、用合适的多锁获取算法可破坏部分条件；超时只是错误处理机制，并不能自动证明不存在死锁。C++17 可用 scoped_lock 协调多互斥量，C++14 可用 std::lock 配合 adopt_lock。

## 原子性、可见性与对象安全

std::atomic 保证该对象操作的原子语义，memory_order 决定同步关系。memory_order_relaxed 适合只要求原子计数的部分场景，不会自动发布其他普通对象内容；release/acquire 可在满足配对关系时发布数据。

```cpp
#include <atomic>
std::atomic<unsigned> processed{0};
void recordProcessed()
{
    processed.fetch_add(1, std::memory_order_relaxed);
}
```

原子类型未必全部 lock-free，实时路径或 ISR 中还需检查具体实现。独立 shared_ptr 副本的控制块安全不保证所指对象字段安全，也不能免除同一 shared_ptr 变量并发修改时的同步。
