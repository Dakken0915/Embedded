# 内核内存与地址映射

## 内核分配接口

| 接口 | 语义 |
| --- | --- |
| kmalloc/kcalloc/krealloc | 常用内核对象分配；按相应接口保证连续性，对大小与 GFP 条件有限制 |
| kfree | 释放相应 kmalloc 家族对象 |
| vmalloc/vfree | 虚拟地址连续，底层物理页不必连续 |
| alloc_pages | 按 order 分配页，返回 struct page 指针 |
| __get_free_pages/free_pages | 相应页分配的虚拟地址接口与释放 |
| kmem_cache_alloc/free | 从指定 slab cache 分配/释放固定类型对象 |
| dma_alloc_coherent/free | 为设备取得一致性 DMA 内存及 DMA 地址，不可用普通 malloc 模型替代 |
| mempool_alloc/free | 在约定条件下使用预留池提高关键路径可用性，不是任意上下文永不失败 |

最大分配大小依配置与碎片状态变化，不能统一写成 4 MB。GFP_KERNEL 可睡眠，不用于硬中断等不能睡眠的路径；GFP_ATOMIC 有其资源和失败限制，不会使所有分配请求可靠成功。


## MMIO 映射与访问

`ioremap` 面向设备 I/O 地址区域，返回 `void __iomem *`；它不是普通堆分配，也不能将任意物理 RAM 都当作设备寄存器映射。映射采用实际系统页粒度，不能固定假设所有 Linux 都是 4096 字节页。非对齐资源可能跨越额外页面，长度应覆盖起点偏移后的完整区间。

平台驱动通常使用 `devm_platform_ioremap_resource(pdev, 0)`，组合资源取得、占用检查和映射；失败返回错误指针，必须 `IS_ERR` / `PTR_ERR` 检查。裸 `ioremap` 对应 `iounmap`，devm 管理的映射不要重复手动释放。

```c
/* Linux 6.6；函数片段，调用者位于 platform probe。 */
#include <linux/io.h>
#include <linux/platform_device.h>

int map_demo_resource(struct platform_device *pdev, void __iomem **out)
{
    void __iomem *base = devm_platform_ioremap_resource(pdev, 0);
    if (IS_ERR(base))
        return PTR_ERR(base);
    *out = base;
    return 0;
}
```

寄存器使用 `readl`、`writel` 等访问器，不能直接转成普通指针读写。读取后修改再写回需要考虑并发、只读位、保留位、写一清零位以及硬件 SET/CLR 别名寄存器；W1C 状态不应套用普通读改写。内存屏障、总线 posted write 和寄存器端序还需遵循设备规范。

## CPU 地址与 DMA 地址

CPU 虚拟地址、CPU 物理地址、DMA 总线地址是不同概念。DMA API 根据设备 DMA mask、IOMMU 和平台一致性建立映射；不能用 `virt_to_phys` 替代 `dma_map_single`。一致性分配返回 CPU 指针及 `dma_addr_t`，交给设备的是后者。

streaming DMA 需要配对 map/unmap，并在 CPU/设备交接时按方向执行相应同步。即使是一致性 DMA 内存，也仍有描述符写入顺序和所有权协议。异步 DMA、IRQ、工作队列停止并同步完成后，才能释放它们可能访问的缓冲区。

进程 VMA、页表、TLB、缺页以及 AArch64 位段示例见 [Linux 内存管理](../Linux应用/Linux内存管理.md)。
