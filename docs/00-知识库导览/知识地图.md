# 知识地图

这套知识库按嵌入式系统的知识边界组织成一条从语言基础到系统交付的路线：越靠前越通用，越靠后越贴近板卡、设备和产品。

## 推荐阅读顺序

1. **基础与工具**：补齐 C/C++、Linux 用户态、构建和脚本能力。
2. **Linux 与驱动**：理解设备模型、设备树、总线和字符设备，再进入具体子系统。
3. **硬件与接口**：用协议时序和电气约束解释 CAN、FPGA、通用外设。
4. **应用与框架**：把采集、处理、显示、通信串成可运行的应用。
5. **工程实践**：用分层、测试、性能分析和故障复盘把知识落到项目。

## 一张系统心智模型

```text
应用 / 业务状态机
        ↓
服务与组件（图像、网络、日志、配置）
        ↓
设备抽象（传感器、显示、输入、存储）
        ↓
Linux 子系统（V4L2 / I2C / USB / GPIO / Input）
        ↓
设备树、BSP、驱动、寄存器与物理信号
```

查问题时沿数据流反向定位：先确认业务输入输出，再确认服务是否收到数据，最后进入设备节点、驱动日志和波形。
