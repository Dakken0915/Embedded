## 挂起、删除与通信

`OSTaskSuspend()` 改变任务可运行性，恢复需要匹配的恢复接口；挂起不等于等待带超时的事件。`OSTaskDel()` 删除内核中的任务对象关联，但应用拥有的文件、缓冲区、设备和动态分配资源仍需明确清理，不能假定内核自动回收全部资源。

启用任务消息队列时，可向任务的私有队列投递消息。消息内容若为指针，发送成功后数据所有权与释放责任仍由应用定义。信号量用于同步或计数，互斥量用于资源所有权，事件标志用于组合条件，不能相互替代所有语义。

Micrium 的初始化、任务管理和中断接口说明可参见 [Kernel Programming Guide](https://docs.silabs.com/micrium/latest/micrium-kernel/04-kernel-programming-guide)；旧版 uC/OS-III 与 SDK 分支的具体函数签名以对应源码为准。

## 状态组合与删除清理

任务可以同时具有等待、超时和挂起条件。删除时不能只从就绪链表移除，必须根据原状态清理相应的内核组织。

| 任务状态 | 清理对象 |
| --- | --- |
| 就绪 | 就绪链表；必要时更新优先级位图 |
| 仅挂起 | 没有就绪节点可移除，处理任务对象 |
| 延时、延时并挂起 | Tick 延时结构 |
| 等待、带超时等待及其挂起组合 | Tick 结构及相应对象等待链 |
| 私有任务队列/私有信号量等待 | 按该功能的特殊等待组织处理，不能假定都有独立对象等待链 |

完成状态相关移除后，旧分支释放任务消息队列中的消息描述符，调用删除钩子，更新任务计数，重置 TCB 并标为删除，最后重新调度。消息描述符回收到内核池不等于消息载荷已由应用释放。

```text
停止新的请求与投递
通知目标任务退出
目标任务释放外设、锁、缓冲区等应用资源
等待并确认没有在途访问
调用删除接口或由任务自行删除
确认 TCB 与栈不再被内核或其他执行流引用后，才回收存储
```

临界区保护内核链表不等于解决应用生命周期。重复删除、复用同一 TCB、同时向已销毁任务投递消息仍可能构成错误；不能保证任意重复操作都安全。持有互斥量时强制删除尤其需要核对版本的持锁清理策略，不能依赖臆测的自动释放。

## 挂起计数与恢复

`OSTaskSuspend` 经校验后进入内部状态处理，常见分支使用 `SuspendCtr` 表示嵌套挂起。恢复须按规则匹配；恢复挂起只移除挂起条件，尚未完成的延时或对象等待不会因此自动满足。空闲任务等受保护任务不能被应用随意挂起或删除。

## 私有队列与消息所有权

启用 `OS_CFG_TASK_Q_EN` 后，`OSTaskQPost` 向指定任务投递消息，接收任务用 `OSTaskQPend` 等待自己的队列。典型接口如下，具体声明以所用分支头文件为准：

```c
void OSTaskQPost(OS_TCB *task, void *message, OS_MSG_SIZE size,
                 OS_OPT option, OS_ERR *error);
void *OSTaskQPend(OS_TICK timeout, OS_OPT option,
                  OS_MSG_SIZE *size, CPU_TS *timestamp, OS_ERR *error);
```

这类队列通常传递指针与长度，不按长度复制载荷。发送成功后应明确由谁拥有消息；发送失败时生产者仍需负责释放。将局部数组地址投递后立即返回，或在消费者处理前覆盖复用，都会破坏消息内容。

任务信号量维护任务的私有计数，适合定向通知；普通信号量是独立同步对象，互斥量包含所有权与继承语义，事件标志组合多个条件，不能仅因它们都能阻塞就相互替换。
