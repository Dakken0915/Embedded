## 就绪位图与同优先级链表

uC/OS-III 通常以较小的优先级数值表示较高优先级，与 FreeRTOS 常见的数值方向相反。可用范围及保留系统优先级由配置决定。

就绪位图记录哪些优先级存在可运行任务，`OS_PrioGetHighest()` 从位图选取最高就绪优先级；每个优先级的就绪链表维护队首、队尾和数量。任务插入尾部及时间片轮转规则共同控制同优先级任务的执行次序。时间片配置为零时的含义须结合具体版本和默认配置读取，不能直接断言永不轮转。

## 位图定位算法

旧内核将优先级按 CPU_DATA 的位宽分组，较高优先级映射到靠前的表项和较高位。`OS_PrioGetHighest` 跳过全零表项，再用前导零数量定位首个置位位。扫描依赖就绪位图非空；内核通常通过空闲任务或其他配置不变量保证它。

下面是相同编码思路的独立 C11 实现，额外检查空表并返回 -1，便于说明边界，不是内核 API。

```c
#include <stddef.h>
#include <stdint.h>
int highestReadyPriority(const uint32_t *table, size_t words)
{
    if (table == NULL || words == 0 || words > 8) {
        return -1;  /* 此示例限制在最多 256 个优先级。 */
    }
    for (size_t word = 0; word < words; ++word) {
        uint32_t mask = UINT32_C(0x80000000);
        for (unsigned bit = 0; bit < 32; ++bit, mask >>= 1) {
            if ((table[word] & mask) != 0) {
                return (int)(word * 32 + bit);
            }
        }
    }
    return -1;
}
```

实现可用 CLZ 指令加速，但某些编译器内建对零输入未定义，因此须先确认对应表项非零。位图的插入和移除必须与链表同步，否则调度可能选到空队列。

## 每优先级就绪链表

一个优先级的就绪表由队首、队尾、节点数构成，TCB 的前后指针链接同级任务。结构关系如下，属于说明性模型：

```c
#include <stddef.h>
struct ReadyNode {
    struct ReadyNode *previous;
    struct ReadyNode *next;
};
struct ReadyList {
    struct ReadyNode *head;
    struct ReadyNode *tail;
    size_t count;
};
```

空链表的首尾均为空，单节点时首尾指向同一节点。新增节点到尾部时，更新原尾节点、必要的队首、队尾和数量；移除最后一个节点时，还需清除对应优先级位图位。所有修改必须处于内核约定的保护范围。

队首是当前该优先级的候选任务；创建时插入尾部避免无条件越过已就绪同级任务。轮转将队首移动到队尾，但只有轮转配置、时间片和调度条件满足时才实际发生，尾插本身不保证任意工作负载下的公平性。
