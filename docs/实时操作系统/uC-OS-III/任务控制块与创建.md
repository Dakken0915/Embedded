## TCB 与任务创建

任务控制块 `OS_TCB` 保存栈指针、入口和参数、优先级、状态、栈边界、时间片以及可选消息队列等信息。

`OSTaskCreate()` 检查 TCB、入口、栈空间、优先级及调用上下文等条件；按配置清理栈并调用 `OSTaskStkInit()` 构造首个上下文，然后初始化 TCB 和可选任务消息队列，调用创建钩子，最后将任务加入就绪结构。调度器已运行时，创建更高优先级就绪任务可能触发调度。

栈大小通常按 `CPU_STK` 元素数量表示，需结合元素宽度换算字节，不能直接套用其他 RTOS 的单位。TCB 和栈的存储期必须覆盖任务存活期间。

### 静态任务对象与周期任务

以下代码采用经典 uC/OS-III 3.x 的 `OS_ERR` 接口，创建优先级为 5、栈容量为 256 个 `CPU_STK` 的任务。调用 `startApplicationKernel()` 前须完成 CPU 与 BSP 的早期初始化；系统 Tick 必须由对应移植和 BSP 正确启用。优先级 5 须在配置允许范围内，且未占用保留的系统优先级。

```c
#include "os.h"

#define APP_STACK_SIZE 256u

static OS_TCB appTaskTcb;
static CPU_STK appTaskStack[APP_STACK_SIZE];

/* 板级函数：执行一次应用处理，不得长期占用 CPU。 */
extern void applicationStep(void);

static void kernelError(void)
{
    /* 错误出口；产品可在此记录错误并进入受控恢复流程。 */
    for (;;) {
    }
}

static void appTask(void *argument)
{
    OS_ERR error;
    (void)argument;

    for (;;) {
        applicationStep();
        /* 相对延时 10 Tick；不等同于固定周期 10 ms。 */
        OSTimeDly(10u, OS_OPT_TIME_DLY, &error);
        if (error != OS_ERR_NONE) {
            kernelError();
        }
    }
}

void startApplicationKernel(void)
{
    OS_ERR error;

    OSInit(&error);
    if (error != OS_ERR_NONE) {
        kernelError();
    }

    OSTaskCreate(&appTaskTcb, "application", appTask, (void *)0,
                 5u, &appTaskStack[0], APP_STACK_SIZE / 10u,
                 APP_STACK_SIZE, 0u, 0u, (void *)0,
                 OS_OPT_TASK_STK_CHK | OS_OPT_TASK_STK_CLR, &error);
    if (error != OS_ERR_NONE) {
        kernelError();
    }

    OSStart(&error);
    kernelError();  /* 调度正常启动后不应到达这里。 */
}
```

`OSTaskCreate()` 中栈指针之后依次传入栈限制、栈容量、任务消息队列容量、时间片、扩展指针、选项和错误输出。栈检查功能还取决于内核配置；数组静态分配不等于栈容量必然足够。签名可对照 [uC/OS-III os.h](https://github.com/weston-embedded/uC-OS3/blob/develop/Source/os.h)，采用 `RTOS_ERR` 的 SDK 分支需要相应调整。

## TCB 字段与数据归属

以下字段来自经典内核分支的功能分组。启用宏、命名和布局随版本变化，不能按表中顺序推算二进制偏移。

| 字段组 | 典型字段 | 含义 |
| --- | --- | --- |
| 上下文 | `StkPtr`、`StkBasePtr`、`StkLimitPtr`、`StkSize` | 当前保存位置、栈区与检查边界 |
| 入口 | `TaskEntryAddr`、`TaskEntryArg`、`NamePtr`、`ExtPtr` | 入口、参数、名称、用户扩展 |
| 调度 | `Prio`、`TaskState`、`NextPtr`、`PrevPtr` | 有效优先级、状态及调度链链接 |
| Tick | `TickNextPtr`、`TickPrevPtr`、`TickCtrMatch`、`TickRemain` | 延时或超时的组织与到期信息 |
| 旧版 Tick 轮 | `TickSpokePtr`、`TickCtrPrev` | 对应旧分支时间轮和周期基准 |
| 等待 | `PendOn`、`PendStatus`、`PendDataTblPtr` | 等待原因、完成状态与等待记录 |
| 时间片 | `TimeQuanta`、`TimeQuantaCtr` | 配额与剩余时间片 |
| 私有通信 | `SemCtr`、`MsgQ`、`MsgPtr`、`MsgSize` | 任务信号量、任务队列与交付结果 |
| 标志与挂起 | `FlagsPend`、`FlagsRdy`、`FlagsOpt`、`SuspendCtr` | 标志等待条件和挂起嵌套 |
| 线程扩展 | `TLS_Tbl`、`RegTbl` | TLS 与任务寄存器表 |
| 统计 | `CPUUsage`、`CtxSwCtr`、`CyclesTotal`、`StkUsed`、`StkFree` | 运行统计与栈观测 |
| 调试与时间测量 | `DbgPrevPtr`、`DbgNextPtr`、`IntDisTimeMax`、`SchedLockTimeMax` | 调试链和最坏屏蔽/锁定时间 |

TCB 内的任务参数通常只保存指针，不复制所指对象。函数返回后仍被任务使用的自动变量、已释放对象或可变的共享参数，都可能造成生命周期错误。

## OSTaskCreate 的内部分阶段流程

1. 按配置检查 ISR 上下文、TCB、任务入口和栈指针。
2. 检查 `stk_size` 不小于最小值、`stk_limit < stk_size`、优先级在范围内且不占用保留项。
3. 初始化 TCB，按栈检查/清理选项填充栈区，按增长方向计算限制位置。
4. 调用 `OSTaskStkInit` 构造可恢复上下文，将返回栈指针写入 TCB。
5. 保存入口、参数、名称、优先级、栈、时间片及扩展信息，初始化启用的任务寄存器和私有消息队列。
6. 调用创建钩子，再在内核保护区域更新优先级位图、就绪链表和任务数量。
7. 若内核已经运行，在允许调度的上下文检查是否需要抢占当前任务。

创建钩子发生在该分支 TCB 基本初始化之后、任务加入就绪链表之前。钩子不能假定新任务已经执行，不能以阻塞调用破坏创建路径。创建失败时应用不得继续启用引用无效任务对象的中断。

## 栈边界与时间片

旧分支对高地址向低地址增长的栈，可由 `base + stk_limit` 建立限制指针；反向增长时采用另一侧计算。`stk_limit` 是检测或限制参数，不应理解为自动创建了硬件保护区；真正保护还取决于 MPU 和端口实现。

启用同优先级轮转时，部分分支将 `time_quanta=0` 解释为使用 `OSSchedRoundRobinDfltTimeQuanta`，再设置 `TimeQuantaCtr`。原始注释中的“0 表示不轮转”与这种代码分支不一致，应以执行路径和配置为准。
