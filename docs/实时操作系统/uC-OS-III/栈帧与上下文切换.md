## 初始栈与上下文切换

`OSTaskStkInit()` 按移植层约定构造可恢复的初始栈帧，包含入口、参数、返回处理及初始状态。首次启动沿恢复路径进入任务，后续切换再保存和恢复实际上下文。

需要保存的寄存器由架构、ABI、异常入口和浮点使用共同决定。Cortex-M 的异常硬件会保存部分寄存器，其余由软件保存；RISC-V 移植须按相应中断与调用约定完成保存。不能笼统认为所有 uC/OS-III 切换都只发生在普通函数调用边界。

## 初始上下文的必要内容

任务尚未运行时没有历史现场，创建函数需要建立与恢复代码匹配的初始帧。它至少要使 CPU 得到正确入口、参数、栈指针和状态；若任务入口错误返回，还应进入 `OS_TaskReturn` 等受控出口，而不是落入无效地址。

| 上下文 | Cortex-M 常见机制 | RISC-V 需要核对的内容 |
| --- | --- | --- |
| 参数 | R0 等初始寄存器 | a0 等参数寄存器 |
| 继续位置 | 硬件异常帧中的 PC | mepc 或端口定义的恢复位置 |
| 返回路径 | LR 与 EXC_RETURN 分工 | ra 与异常返回指令分工 |
| 状态 | xPSR、异常返回状态 | mstatus 等特权状态 |
| 扩展 | 浮点帧、控制寄存器 | 浮点/向量状态及扩展配置 |

标准 RISC-V ABI 中，a0～a7 和 t 寄存器通常为调用者保存，s 寄存器为被调用者保存；gp、tp 还有专门约定。原笔记将 x5～x15 一概称为 Non-volatile 并不正确。异步中断可以打断任意指令，必须与异常封装共同保证全部必要现场，不能仅依据普通函数调用约定删除寄存器。

## RISC-V 栈对齐与寄存器变体

旧 SDK 示例用掩码把地址对齐到 8 字节，但标准 ILP32/LP64 ABI 通常要求函数入口 16 字节栈对齐；ILP32E 等变体有不同约束。必须同时匹配编译器 ABI、寄存器数量、浮点 ABI 和端口代码，不能将 8 字节当作全部 RISC-V 的要求。具体约定见 [RISC-V psABI](https://riscv-non-isa.github.io/riscv-elf-psabi-doc/)。

以下独立 C11 辅助函数只演示向下对齐及合法性检查，不代表完整任务栈初始化。对齐会减少可用空间，调用方还须确认剩余容量足以容纳上下文。

```c
#include <stddef.h>
#include <stdint.h>
int alignStackTop(uintptr_t end, size_t alignment, uintptr_t *top)
{
    if (top == NULL || alignment == 0 ||
        (alignment & (alignment - 1)) != 0) {
        return -1;
    }
    *top = end & ~((uintptr_t)alignment - 1u);
    return 0;
}
```

## 任务级与中断级切换

`OS_TASK_SW` 是端口入口，可能触发异常，也可能采用其他切换机制；`OSIntCtxSw` 处理已经位于中断退出路径的切换。两条路径如何共享保存恢复代码由端口决定。

笔记中向 `0xE080100C` 的 bit 0 写 1，是特定芯片的中断控制约定，不能作为 RISC-V 通用寄存器。可将其抽象为以下伪代码：

```text
读取芯片定义的调度中断控制寄存器
按寄存器访问规则设置调度请求位
执行该平台要求的屏障
从触发函数返回；在允许响应时进入相应异常
异常入口保存上下文，选择 TCB 并恢复目标上下文
```

写寄存器后不保证一定在 `ret` 之前进入异常；屏蔽状态、优先级、流水线与控制器行为都会影响响应时刻。读改写也不适合所有写一置位/清零寄存器，必须遵循芯片手册。
