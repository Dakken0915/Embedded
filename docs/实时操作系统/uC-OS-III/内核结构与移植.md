# uC/OS-III


## 内核、移植层与板级支持

uC/OS-III 的通用内核处理任务、优先级、时间、信号量、消息队列、互斥量和事件标志。CPU 移植层负责寄存器上下文、栈布局、临界区和异常入口；BSP 提供具体板卡的时钟、节拍和外设初始化。应用配置定义启用的功能、任务数量、栈和统计选项。

| 组成 | 典型文件或目录 | 职责 |
| --- | --- | --- |
| 内核核心 | `os_core.c`、`os_task.c`、`os_prio.c` | 初始化、调度、任务与就绪结构 |
| 时间管理 | `os_tick.c`、`os_time.c`、`os_tmr.c` | 节拍、延时、软件定时器 |
| 同步通信 | `os_sem.c`、`os_q.c`、`os_mutex.c`、`os_flag.c` | 任务间同步与消息 |
| CPU 与移植 | `uC-CPU`、`Ports`、`os_cpu.h` | 指令、异常、栈与上下文切换 |
| 库与配置 | `uC-LIB`、`os_cfg.h`、`os_cfg_app.h` | 基础库及裁剪配置 |
| BSP 与适配 | `bsp.c`、CSI 适配文件等 | 板级支持及 SDK 接口转换 |

不同 SDK 的目录名和 API 包装可能不同。RISC-V SDK 中的 `rv32_16gpr`、`rv32_32gpr`、`rv32f_32gpr`、`rv32fd_32gpr` 等变体与整数寄存器数量、浮点扩展和 ABI 对应，不能混用上下文汇编。


## 初始化与启动

```text
板级早期初始化
    → OSInit()
    → 建立内核对象和系统任务
    → OSTaskCreate() 创建应用任务
    → OSStart()
    → OS_PrioGetHighest() 选择就绪优先级
    → OSStartHighRdy() 恢复首个任务上下文
```

`OSInit()` 初始化内核状态；`OSInitHook()` 提供移植层初始化入口，可设置中断栈等架构相关资源。`OSStart()` 在准备完成后启动调度，正常启动路径不应当作一个普通返回的函数使用。应用需检查各接口的错误输出。

Cortex-M 移植必须将 PendSV 与 SysTick 向量连接到真正的内核处理程序。仅把弱默认处理程序改名而保留 `B .` 死循环不能完成移植。节拍频率、处理器时钟和中断优先级须与配置一致。

## 工程集成与配置依赖

以 Cortex-M4 工程为例，源文件应按内核 Source、CPU 支持、内核 CPU Port、库、BSP 和配置区分。内核移植的汇编、CPU 库汇编及 C 文件必须与 GCC、IAR 或 Arm 工具链一致；不能将 RealView 汇编直接交给 GCC 汇编器。

配置头通常包括 `os_cfg.h`、`os_cfg_app.h`、`cpu_cfg.h`。应用定义控制对象裁剪、Tick 频率、优先级数量、系统任务和栈容量；`os_cfg_app.c` 等文件据此建立对象。头文件搜索路径只能使声明可见，不能替代把所需源文件加入构建。

| 模块 | 补充职责 |
| --- | --- |
| `os_mem.c` | 固定块内存管理 |
| `os_msg.c` | 消息描述符与消息池 |
| `os_pend_multi.c` | 特定旧分支的多对象等待支持 |
| `os_stat.c` | 统计任务、CPU 使用率和栈检查 |
| `os_dbg.c`、`os_var.c` | 调试信息与内核变量组织，文件划分依分支 |
| `adapter/csi_ucos.c` | CSI API 到原生内核语义的适配 |
| `csi.mk`、`package.yaml` | 特定 SDK 的构建与组件配置 |

Cortex-M 向量表的 PendSV、SysTick 项应引用最终链接的真实内核异常入口。向量表定义、符号可见性、弱别名和链接结果需要一致；同名弱死循环即使能够链接也不能完成调度。初始化系统时钟后，Tick 重装载值须使用实际核心或选定时钟频率。

## 初始化顺序及失败语义

`OSInit` 建立优先级表、就绪表、等待和时间管理、消息资源以及启用的系统任务；`OSInitHook` 参与 CPU 移植初始化。调用成功后才能创建应用对象和执行 `OSStart`。内核启动前不应让调用 OS 服务的外设中断提前运行。

以下为根据旧分支整理的启动机制伪代码，省略参数校验和跟踪宏，不是用于覆盖内核的实现：

```text
OSStart(error):
    如果内核已运行：返回“已经运行”错误
    highestPriority = 从就绪位图选出最高优先级
    next = 该优先级就绪链表的队首
    初始化当前/最高就绪优先级和 TCB 指针
    标记内核运行
    由 OSStartHighRdy 恢复首个任务
    若该入口意外返回：报告致命返回错误
```

启动依赖至少存在可执行任务。部分版本保留空闲任务维持此不变量，部分 SDK 可以裁剪，必须核对实际配置，不能无条件扫描空位图。

## 中断栈初始化钩子

旧 RISC-V SDK 的钩子清零 `OSCfg_ISRStkBasePtr` 指定的区域，并计算异常栈顶。其机制可表达为：

```text
确认中断栈基址有效、元素数非零
按 CPU_STK 元素清理中断栈
根据该移植的栈增长方向和对齐要求计算栈顶
将结果交给异常入口使用
```

`base + size - 1` 代表最后一个元素，`base + size` 代表尾后地址，两者是否适合作为初始 SP 由端口压栈顺序决定。不能把笔记中的单一计算式复制到所有架构；若 size 为零还会产生下溢。
