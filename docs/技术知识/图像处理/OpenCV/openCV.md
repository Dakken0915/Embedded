# OpenCV 图像处理

## 嵌入式图像处理链路

典型图像处理链路为：

```text
摄像头采集 → 像素格式转换 → 缩放或感兴趣区域提取 → 算法处理 → 结果叠加 → 显示或网络传输
```

系统设计需要明确输入图像的分辨率、像素格式、行跨度、帧率和缓冲区生命周期。图像处理的主要开销通常来自内存搬运和格式转换，不能只依据算法的理论复杂度评估性能。

## 颜色空间与格式

常见输入格式包括 YUYV、NV12 和 MJPEG。YUYV 属于未压缩的 YUV 格式，MJPEG 需要先解码，NV12 适合部分硬件编解码器。转换到 BGR 或 RGB 后才能直接使用许多 OpenCV 算法，但转换会增加内存带宽和处理时间。

## 性能与资源约束

- 尽量复用采集缓冲区，减少不必要的拷贝。
- 在进入检测器前降低分辨率，或只处理有效感兴趣区域。
- 分别测量采集、格式转换、算法、显示和传输阶段的耗时。
- 线程退出时释放模型、图像缓存和设备句柄，空帧与异常输入必须作为错误路径处理。

## 人脸检测的基本流程

```text
V4L2 YUYV/MJPEG → 解码或颜色转换 → 缩放/ROI → 检测器 → 结果叠加 → LCD/HTTP
```

模型文件路径、输入尺寸、置信度阈值和检测周期应作为明确配置保存。开发阶段可先使用静态图像验证算法，再接入摄像头，以便区分算法问题与硬件采集问题。
