# ARM 与 RISC-V

## 架构范围

ARM 的 Cortex-M、Cortex-R 和 Cortex-A 面向不同场景，寄存器和异常模型不能混为一谈。RISC-V 同样需要明确 RV32/RV64、扩展集合以及是否实现 S 模式、MMU 和特定中断控制器。

| 项目 | Cortex-M | AArch64 | RISC-V |
| --- | --- | --- | --- |
| 基本整数寄存器 | R0～R15，包含 SP、LR、PC | X0～X30；SP 与零寄存器编码具有上下文含义 | RV32I/RV64I 为 x0～x31；嵌入式 E 基础变体数量较少 |
| 零寄存器 | 无专用零寄存器 | XZR/WZR | x0 恒为零 |
| 异常处理 | NVIC、异常向量表 | 异常级和异常向量 | trap 向量、CSR 与具体中断控制器 |
| 特权模型 | Thread/Handler 模式与特权控制 | EL0～EL3，实际实现可少于四级 | M 模式必须实现；S、U 等按实现提供 |

## 上下文保存

典型 Cortex-M 异常入口自动保存 R0～R3、R12、LR、PC 和 xPSR，处理程序或 RTOS 移植层还需保存其余必要寄存器。浮点上下文与扩展栈帧取决于处理器和配置。

AArch64 异常入口保存返回地址与处理器状态到相应系统寄存器，通用寄存器由软件保存。不能将 Cortex-M 的八字硬件压栈机制套用到 AArch64。

RISC-V 基本 trap 入口更新 `xepc`、`xcause`、`xtval` 和状态 CSR，通用寄存器通常由软件保存。具体 MCU 的中断扩展可能提供额外功能，不能仅凭指令集名称推断中断延迟。

## 指令编码与工具链

AArch64 指令为 32 位；AArch32 包含 ARM 和 Thumb 指令状态。RISC-V 基础指令通常为 32 位，C 扩展提供 16 位压缩编码。移植软件时还要匹配 ABI、浮点约定、端序、栈对齐和所用扩展。

## 内存保护与地址转换

Cortex-M 常见 MPU 用于区域权限控制，通常不提供 Cortex-A Linux 所需的完整虚拟内存模型。AArch64 的 MMU 提供页表转换和权限检查。

RISC-V 的 PMP 负责物理内存访问权限控制，具有 S 模式和分页扩展的实现可使用 Sv32、Sv39、Sv48 等地址转换模式。PMP 不等价于 MMU，也不能直接等同于 TrustZone 的安全世界划分。

跨架构的共享内存与设备访问需要区分编译器约束、内存屏障和缓存维护。`volatile` 不能替代原子操作、DMA 缓存一致性处理或 CPU 内存屏障。

## 流水线与 ISA 的边界

取指、译码、执行、访存、回写组成经典五级流水线模型，但 RISC-V 不强制所有处理器采用五级，也不强制顺序执行。ARM 同样包含不同系列与微架构，不能用一个统一流水线深度概括。

数据冒险可用旁路、停顿或调度处理，控制冒险可通过分支预测及预测失败后的刷新处理，结构冒险来自共享执行资源冲突。增加级数可能提高可达频率，也可能增加分支代价和控制复杂度，并非级数越多性能必然越高。
