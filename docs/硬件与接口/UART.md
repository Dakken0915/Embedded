# UART 与串口通信

UART 是异步串行接口。通信双方不共享时钟，须约定波特率、数据位、校验和停止位。每帧通常包含起始位、数据位、可选校验位和停止位；空闲状态通常为高电平。UART 是逻辑接口，不等同于 RS-232 或 RS-485 电气层。

## 初始化与 GPIO

1. 使能 GPIO 与 UART 外设时钟。
2. 将 TX 配置为外设复用输出，将 RX 配置为外设输入；具体上下拉和引脚复用由芯片及板级电路决定。
3. 配置波特率、数据位、校验、停止位及收发模式。
4. 按传输规模选择轮询、中断或 DMA，并配置相应中断和优先级。
5. 清理遗留状态后使能 UART。

外设复用输出与普通 GPIO 输出的区别在于信号由外设模块驱动。波特率分频应根据该 UART 实际输入时钟计算，APB 分频、过采样模式与误差约束不可忽略。

## 中断与 DMA

接收数据寄存器非空产生 RXNE 类事件，发送数据寄存器可写产生 TXE 类事件，最后一个停止位发完通常另有 TC 类状态。TXE 仅表示发送寄存器可装入下一字节，不代表线路已经发送完毕。

DMA 半传输 HT 与传输完成 TC 表示 DMA 对设定缓冲区的搬运进度。若长度不定，硬件空闲线 IDLE 可用于识别一段时间未出现新字节，但接收还须配合 DMA 写入位置、缓冲区回绕和帧协议处理。错误中断应记录并清除过载、校验、帧错误等状态。

## 帧边界、流控与校验

串口是字节流，不能认为一次中断或 DMA 回调就是一条完整业务消息。可使用固定长度、长度字段、转义分隔符或空闲间隔定义边界。长度字段须验证上限，环形缓冲须检查覆盖。

硬件 RTS/CTS 通过额外信号线控制发送节奏；软件 XON/XOFF 会占用特定数据字节，不适合未经转义的任意二进制负载。校验位只能检测有限类型的单帧错误，复杂协议通常还需要帧校验和序号。

## RS-485 半双工

RS-485 收发器的 DE/RE 控制发送与接收方向。驱动器应在首个起始位前切换到发送，在 UART 的 TC 标志确认最后一个停止位完成后再释放总线；DMA 完成只代表内存到外设搬运结束。总线终端、偏置、共模范围和支线长度须按拓扑设计。

## printf 重定向

标准 C 库的底层输出钩子因工具链而异。下例展示 fputc 适配方式；UART 写函数应有超时并返回错误，不能在 ISR 中无界轮询输出。

```c
#include <stdint.h>
#include <stdio.h>
extern int uartWriteByte(uint8_t byte);

int fputc(int character, FILE *stream)
{
    (void)stream;
    if (uartWriteByte((uint8_t)character) != 0) {
        return EOF;
    }
    return (unsigned char)character;
}
```

Arm C 库、newlib 和厂商库的重定向符号与换行规则不同；MicroLIB 仅是特定工具链选项，并非所有工程必须启用。
