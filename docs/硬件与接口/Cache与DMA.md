# Cache、DMA 与多核一致性

## Cache Line 与映射

Cache 以缓存行为单位管理数据，常见 32 或 64 字节，但大小须查处理器。直接映射将内存块固定到一个缓存位置，全相联允许放入任意位置，组相联固定组但允许组内多路选择。硬件相联查找并不等于软件逐项遍历。

写回 Cache 的脏数据可能尚未进入内存，写直达则有不同写入策略。不同核心频繁修改同一缓存行的独立变量可能产生伪共享，影响性能；单纯字段相邻不总是越好。

## DMA 地址与所有权

DMA 控制器使用设备可见地址，未必等于 CPU 物理地址；IOMMU、总线窗口和地址宽度都可能改变映射。Linux 中必须使用 DMA API 取得 dma_addr_t，不能把用户虚拟指针或任意 virt_to_phys 结果直接交给设备。见 [Linux DMA 指南](https://www.kernel.org/doc/html/latest/core-api/dma-api-howto.html)。

非一致性平台中，CPU 写后供设备读通常需要清理对应 Cache；设备写后供 CPU 读通常需要按平台规则同步或失效。操作范围须覆盖整缓存行，并避免与其他脏对象共享同一行而误丢数据。Linux 驱动按映射方向及 dma_map/sync/unmap 生命周期处理，不能再无条件叠加手写缓存维护。

## DMA 传输组织

外设数据寄存器常使用固定地址，内存缓冲区按字节或字递增；传输宽度、对齐、FIFO 和突发长度必须匹配。DMA 完成只表明相应搬运阶段完成，不一定意味着 UART 最后停止位或 SPI 最后一个时钟已输出。

双缓冲将缓冲区分为设备所有和处理方所有，在完成事件处交换。环形 DMA 可以由部分控制器硬件实现，不能一概说 DMA 不会环绕；CPU 必须跟踪读写进度、半满/全满事件和越界覆盖。

生产速率长期大于消费速率时，任何有限双缓冲或环形缓冲最终都会满，必须定义背压、丢旧帧、丢新帧或停止输入策略。增加缓冲可吸收短时抖动，也可能增加端到端延迟。

## DMB、DSB、ISB 与内存属性

在相应 ARM 架构中，DMB 约束规定范围内的内存访问顺序，DSB 还等待规定操作完成，ISB 同步指令执行环境。屏障不自动等于 Cache clean/invalidate，也不替代对 Device/Normal、可缓存与共享属性的正确配置。

volatile 主要影响编译器访问语义，内存属性影响硬件行为，屏障影响排序与完成；设备寄存器与 DMA 缓冲区可能需要三者按平台规则配合，而不是全部加上就一定正确。

## SMP、NUMA 与原子协议

SMP 的多个处理器可运行共享内存中的任务，必须同时处理互斥、内存排序与缓存一致性。NUMA 还区分本地与远端内存访问代价。硬件缓存一致性不消除语言层的数据竞争，关本核心中断也不能阻止其他核心访问。
