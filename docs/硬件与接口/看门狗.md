# MCU 看门狗

看门狗检测软件是否在约定时限内持续取得进展，并在故障时触发中断或复位。喂狗策略必须体现系统健康状态，不应由一个可能独自卡住或持续运行的高优先级任务无条件执行。

## 独立看门狗

IWDG 通常采用独立低速时钟，主时钟故障时仍可工作。初始化依芯片配置写保护解锁、分频与重载值、启动计数器。部分芯片启动后不可软件关闭。内部 RC 频率有公差，最短和最长超时均应按规格计算。

## 窗口看门狗

WWDG 通常使用总线时钟计数，并设定允许喂狗的时间窗口。窗口开启前喂狗或超过下限仍未喂狗都可能触发复位；总线时钟停止时其行为与 IWDG 不同。实际窗口值须按计数器递减公式及芯片时钟配置计算。

| 项目 | IWDG | WWDG |
| --- | --- | --- |
| 常见时钟 | 独立低速时钟 | APB 等系统时钟 |
| 喂狗限制 | 超时前刷新 | 只允许在规定时间窗刷新 |
| 典型用途 | 主时钟失效后的兜底 | 检测过早或过晚服务等时序异常 |
| 可否关闭 | 依器件，常见为启动后不可关闭 | 依器件配置 |

## 多任务健康管理

关键任务按周期更新进度计数或健康状态，健康管理任务检查所有预期进度、队列积压和关键事务后，才执行喂狗。升级写 Flash、低功耗切换和调试停机可能需要调整超时策略，但不应在健康检查失败时通过单一任务继续掩盖故障。

复位后读取并保存复位原因，结合持久化崩溃计数进行受控恢复。重复看门狗复位可能需要进入安全模式或回滚升级映像。
