# I2C 总线

I2C 使用 SCL 与 SDA 两根开漏/开集电极信号线并配合上拉。器件只能主动拉低总线，逻辑高由上拉电阻形成。总线电容、上拉阻值、线长和速率共同约束上升时间。

## 条件与数据传输

- SCL 为高时 SDA 从高变低形成 START；SDA 从低变高形成 STOP。
- 普通数据传输期间，SCL 为高时 SDA 保持稳定；数据位在时钟低电平阶段改变。
- 每个字节后有一个 ACK/NACK 时钟位，由接收方拉低 SDA 表示 ACK。
- 控制器发出的地址字段之后还有读写方向位；7 位地址与线上 8 位地址字节不能混淆。
- 重复起始可在不释放总线的情况下改变传输方向或继续事务。

寄存器读操作常由 START、从地址+写、寄存器索引、重复 START、从地址+读、数据和 STOP 构成。具体寄存器宽度、地址顺序、自增和读后行为以器件协议为准。

## 仲裁、时钟拉伸与初始化

多控制器仲裁期间，发送端释放 SDA 表示逻辑高；若采样到低电平，说明其他控制器发送显性低位，该控制器退出当前仲裁。器件可通过保持 SCL 低实现时钟拉伸，但控制器对拉伸及超时的支持依实现而异。

控制器初始化需使能外设与 GPIO 时钟，选择正确复用功能，配置时钟频率、上升时间、地址模式和超时，然后检查 BUSY/错误状态。GPIO 上拉不能弥补错误电压域或过大总线电容。

## Linux I2C 子系统

I2C adapter 表示控制器，`i2c_client` 表示总线上地址化设备，设备驱动使用 I2C/SMBus transfer API。设备树描述兼容字符串、地址、中断和供电等资源；业务代码不应自行用 GPIO 拼接总线波形替代标准控制器驱动。

排查时检查供电、地线、上拉、地址、ACK、重复起始和时序；Linux 可结合 `i2cdetect`、`i2cget` 与 `i2ctransfer`，但扫描命令可能对某些器件产生副作用，应先核实设备协议。
